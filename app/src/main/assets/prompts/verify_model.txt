这一章的知识由模型自己提供，没有用户资料可以对照。所以核验的目标不是"和资料是否一致"，而是四件事：推演是否真的走通、内容是否自洽没有硬伤、章节计划（契约）是否完成、读起来像不像小说。

## 1. 推演是否真的走通

本章声明的推演骨架是：
{derivationChain}

正文有没有真的走完这条路？还是中间跳步、或者某个概念是被"突然掏出来"的？

- `broken_derivation`：某个概念登场前，读者并没有被推到"这里缺一块"的位置，属于凭空出现。
- `missing`：本章应当想通的问题（见下）在正文中没有真的被回答，只是提了个名字。

## 2. 内容是否自洽、是否有硬伤

- `contradiction`：正文前后自相矛盾，或与本章知识点的定义冲突。
- `overreach`：把一个有地区差异、版本差异或学界分歧的说法，写成了确定无疑的通行结论。
- `fabrication`：**编造了具体出处** —— 条文编号、判例名称、统计数字、人名年份、机构名称。这是无资料模式下最严重的问题，必须逐条揪出来。规则内容本身可以讲，伪造出处不行。

## 3. 章节计划（因果契约）是否完成

本章计划与契约：
{chapterPlan}

对照契约逐项检查正文，发现契约要求没有兑现时报告：

- `no_application`：概念被讲解，但没有被任何人物用于判断、选择、行动或排除错误方案。
  注意：只有契约要求应用（APPLY / CONTRAST / ASSESS 类型，或契约的 `appliedNodeTitles` 非空）时才需要这一项。
  纯粹的 INTRODUCE / REVIEW 章节不强制应用，不要误报。
- `missing_result`：人物确实行动/判断了，但正文没有给出任何可观察的结果或后续——行动悬空。
  回顾、解释性段落不需要"改变世界"式的结果，不要误报。
- 契约的 `introducedNodeTitles` 里的节点只是被提了个名字而没有讲透 → 用 `missing` 报告。

## 4. 读起来像不像小说（文风）

这本书是小说，不是讲义。以下形态属于硬伤，报告 `style`：

- `style`：通篇是无名"他"或"你"的推理独白，没有任何有名有姓的人物承载情节——整章级问题，`blockId` 填 null；若只有某几段如此，填那几段的 `blockId`。
- `style`：教科书腔的段落——目录式罗列、以定义开头、"可见/综上所述"式的说教总结。能定位到段落就填 `blockId`。
- `style`：同一口头禅在多处原样复读（同一句过渡句出现两次以上）。填其中一处的 `blockId`。

分寸：文风检查抓的是"明显不像小说"的硬伤。某段只是写得平实、不够文采，**不要报**；拿不准就不报。

## 5. 哪些内容需要学习者自己去核对

把正文里**读者不应当只信模型一家之言**的断言列进 `unverifiedClaims`：涉及具体数字门槛、期限、地区差异、近年修改、各家说法不一的地方。
这不是错误，是提示。宁可多列，不要漏列——学习者据此决定哪些内容要去查权威出处。

## 输出

`issues` 数组，每项包含：`type`、`blockId`、`message`（具体指出问题在哪、为什么是问题）、`suggestedFix`。没有问题时 `issues` 为空数组。

`type` 只能用上面列出的那几个值，原样填写，不要自己改写或新造。

`blockId` 必须原样复制正文里那一段的 `[blockId: xxx]`。这个字段决定用户能不能**只重写出问题的那一段**：
- 填对了：用户可以只改这一段，整章其余部分一个字不动。
- 定位不到具体段落（例如「全章推演的节奏偏快」）就填 null。这很正常，如实填。
- **填一个不存在或者不相干的 blockId 是最坏的情况**：用户会打开一段没有问题的正文，看不出问题在哪。宁可填 null。

`unverifiedClaims` 数组，每项一句话，写清"哪个断言需要核对什么"。

## 契约检查（checks）

除 `issues` 外，还要输出 `checks` 数组：**对契约的 `appliedNodeTitles` 和 `introducedNodeTitles` 里的每个知识点，逐项给出正文证据判定**：

```json
{
  "nodeTitle": "被检查的知识点标题（必须与契约中的标题一致）",
  "claim": "APPLIED",
  "evidence": "PRESENT | PARTIAL | ABSENT | UNKNOWN",
  "evidenceBlockIds": ["定位到正文的 blockId，无证据就空数组"],
  "comment": "一句说明"
}
```

`evidence` 判定口径（**防误报，宁可 UNKNOWN 不要虚报 PRESENT**）：
- `PRESENT`：正文有明确的应用/引入证据，且你能定位到具体段落（填 `evidenceBlockIds`）；
- `PARTIAL`：正文提到了这个概念，但没有真正用起来（只提了名字、没走完判断/选择/行动）；
- `ABSENT`：正文根本没有对应内容；
- `UNKNOWN`：你无法判断（例如正文缺失、上下文不足）——**不要因为「没找到证据」就直接写 ABSENT**，区分「确实没有」和「无法判断」。

`claim`：`APPLIED`（契约要求应用）、`INTRODUCED`（契约要求首次引入）、`RESULT`（应用后是否有可观察结果）。
## 证据边界（硬约束，违反即判定错误）

**只能依据正文 blocks 判定 `evidence`。** 契约、路线、声明、检查目标或模型自身知识都不是正文证据。

- 正文未出现目标概念，且没有表达该概念所需的关键事实关系 → 必须判 `ABSENT` 或 `UNKNOWN`，**不得判 `PRESENT`**；
- 「契约/本章计划/推演骨架里提到这个概念」不等于「正文引入了这个概念」——声明不是证据；
- 只有当你能在正文里指出**具体段落**承载了该概念的引入/应用时，才能判 `PRESENT`（并填 `evidenceBlockIds`）；
- 拿不准时判 `UNKNOWN`，宁可 UNKNOWN 不要虚报 PRESENT。
