你在为一个学习者整理一门学科的「知识主干」。**这一次没有提供任何资料，知识全部由你自己提供。**

学习者明确希望这样做：给了资料，你往往会被资料的编排绑住，讲成教材的样子；不给资料，你才能真正站在整门学科之上，取其精华、去其糟粕，讲出那条最本质的路径。所以请充分动用你对这门学科的理解，按你认为**最容易让人真正想通**的顺序来组织，而不是按任何一本教材的目录。

## 你要做的事

把这门学科整理成一条**演进主干**。主干上的每一站都是一个「问题 → 回答」：

- 上一站已经解决了什么
- 于是暴露出什么新问题
- 为了回答这个新问题，出现了什么制度／概念
- 这个制度自身又留下什么没解决的口子（引出下一站）

## 输出结构

- `nodes`：知识节点。层级不超过 3 层，用 `parentTitle` 表达父子关系，根节点 `parentTitle` 为 null。
- 节点数量：入门 14-22 个，考试 24-36 个，专业 32-44 个。
- 每个节点必须给出：
  - `definition`：这个概念解决的是什么问题（不要写词典式定义，要写"它是为了回答什么才存在的"）
  - `arisesFrom`：它从哪个前序概念、因为什么缺口才出现（一句话；根节点写这门学科的起点问题）
  - `leadsTo`：它自身没能解决、因而引出下一个概念的那个口子（一句话）
  - `prerequisites`、`related`、`confusions`、`examples`
  - `sourceRefs`：留空数组
- `chains`：3-8 条演进链。每条 `nodeTitles` 是一串节点标题，按「前一个制度长出后一个」的顺序排列，`theme` 一句话说明这条链在回答什么，`opening` 说明这条链从学习者能直接感知的什么处境开始讲。
  这些链会被直接用作章节骨架，所以每条链必须能独立讲成一段连贯推演。
- `gaps`：这门学科里**存在地区/版本差异、近年有修改、或各家说法不一**的地方。学习者需要知道哪些内容不能只信你一家之言。
- `conflicts`：学界或实务中确实存在的对立观点。列出对立双方各自的立场，**不要替学习者裁决**。

## 硬性要求（无资料模式）

1. `arisesFrom` 与 `leadsTo` 必须真的咬合：把 nodes 按 chains 串起来读，应当读出一条连续推理。
2. 只写你有**充分把握**的通行结论。不确定的、可能因地区或年份而不同的，一律写进 `gaps`，不要写进 `definition` 装作确定。
3. **不要编造具体的条文编号、判例名称、统计数字、人名年份**。需要指向具体规定时，只描述规则内容本身（"法律要求……"），不要伪造出处。确有必要提到出处时，把它列进 `gaps` 让学习者自行核对。
4. 你的知识可能已经过时。凡是涉及"最新规定""现行标准"的，写进 `gaps`。
5. 只输出 JSON 对象，不要输出任何其他文字或代码块标记。
