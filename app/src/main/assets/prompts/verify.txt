对照资料片段核验本章正文。核验四件事：知识是否有依据，推演是否走通，章节计划（契约）是否完成，读起来像不像小说。

## 1. 知识是否有依据

- `unsupported`：正文出现资料无法支撑的知识断言。
- `contradiction`：正文表述与资料矛盾。
- `citation_error`：sourceRefs 引用错误或缺失，或引用的片段与该段内容无关。
- `fabrication`：编造了资料中没有的具体出处——条文编号、判例名称、统计数字、人名年份，
  或填了一个下面片段列表里根本不存在的片段 ID。
- `scope_error`：把只在某个法域、或只在某个生效时间之后成立的规则讲成了普适规则。
  每段资料都标了它的法域与生效时间，据此判断。

## 4. 读起来像不像小说（文风）

这本书是小说，不是讲义。以下形态属于硬伤，报告 `style`：

- `style`：通篇是无名"他"或"你"的推理独白，没有任何有名有姓的人物承载情节——整章级问题，`blockId` 填 null；若只有某几段如此，填那几段的 `blockId`。
- `style`：教科书腔的段落——目录式罗列、以定义开头、"可见/综上所述"式的说教总结。能定位到段落就填 `blockId`。
- `style`：同一口头禅在多处原样复读（同一句过渡句出现两次以上）。填其中一处的 `blockId`。

分寸：文风检查抓的是"明显不像小说"的硬伤。某段只是写得平实、不够文采，**不要报**；拿不准就不报。

## 输出

`issues` 数组，每项包含：`type`、`blockId`、`message`（具体指出问题在哪、为什么是问题）、`sourceRefs`（相关来源）、`suggestedFix`（建议修改）。没有问题时 `issues` 为空数组。

`type` 只能用上面列出的那几个值，原样填写，不要自己改写或新造。

`blockId` 必须原样复制正文里那一段的 `[blockId: xxx]`。这个字段现在决定用户能不能**只重写出问题的那一段**：
- 填对了：用户可以只改这一段，整章其余部分一个字不动。
- 定位不到具体段落（例如「全章语气不一致」）就填 null。这很正常，如实填。
- **填一个不存在或者不相干的 blockId 是最坏的情况**：用户会打开一段没有问题的正文，看不出问题在哪。宁可填 null。

`unverifiedClaims` 输出空数组（有资料模式不需要）。

## 契约检查（checks）

除 `issues` 外，还要输出 `checks` 数组：**对契约的 `appliedNodeTitles` 和 `introducedNodeTitles` 里的每个知识点，逐项给出正文证据判定**：

```json
{
  "nodeTitle": "被检查的知识点标题（必须与契约中的标题一致）",
  "claim": "APPLIED",
  "evidence": "PRESENT | PARTIAL | ABSENT | UNKNOWN",
  "evidenceBlockIds": ["定位到正文的 blockId，无证据就空数组"],
  "comment": "一句说明"
}
```

`evidence` 判定口径（**防误报，宁可 UNKNOWN 不要虚报 PRESENT**）：
- `PRESENT`：正文有明确的应用/引入证据，且你能定位到具体段落（填 `evidenceBlockIds`）；
- `PARTIAL`：正文提到了这个概念，但没有真正用起来（只提了名字、没走完判断/选择/行动）；
- `ABSENT`：正文根本没有对应内容；
- `UNKNOWN`：你无法判断（例如正文缺失、上下文不足）——**不要因为「没找到证据」就直接写 ABSENT**，区分「确实没有」和「无法判断」。

`claim`：`APPLIED`（契约要求应用）、`INTRODUCED`（契约要求首次引入）、`RESULT`（应用后是否有可观察结果）。
## 证据边界（硬约束，违反即判定错误）

**只能依据正文 blocks 判定 `evidence`。** 契约、路线、声明、检查目标或模型自身知识都不是正文证据。

- 正文未出现目标概念，且没有表达该概念所需的关键事实关系 → 必须判 `ABSENT` 或 `UNKNOWN`，**不得判 `PRESENT`**；
- 「契约/本章计划/推演骨架里提到这个概念」不等于「正文引入了这个概念」——声明不是证据；
- 只有当你能在正文里指出**具体段落**承载了该概念的引入/应用时，才能判 `PRESENT`（并填 `evidenceBlockIds`）；
- 拿不准时判 `UNKNOWN`，宁可 UNKNOWN 不要虚报 PRESENT。


只输出 JSON 对象，不要输出任何其他文字。
