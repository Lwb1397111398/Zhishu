你要为一门学科设计一条**连续的讲述路线**，让学习者跟着走一遍，学科自己就长出来了。

## 先明确这不是什么

不是"小说 + 知识点插播"。不要设计一个探案故事、再把知识塞进人物对话里。学习者要的是：**沿着一条线往前走，走着走着，这门学科自己出现了**，而不是有人突然掏出几个名词让他背。

## 章节怎么切

**一章围绕一条主要的推演路径展开，但允许跨链、拆链、合并和回顾**——具体怎么切由本章的**章节类型**与学习者负荷决定，不需要和知识地图里的演进链一一对应：

- 一条地图演进链太长，可以拆成多章，中间必须用 `openingHook` / `closingHook` 保持衔接；
- 两条相关的链可以合并进一章，前提是这一章仍然有一条说得清的推演主线；
- 已经讲过的知识点可以在后续章节再次出现，作为**应用、辨析或回顾**，而不是重新介绍一遍。

每章必须给出 `derivationChain`，一句话说清本章的推演骨架——
**从哪个已经成立的东西出发 → 遇到什么它解决不了的问题 → 于是长出什么。**

例如（民法）：
> 法律已经承认了人 → 但刚出生的人无法自己签合同 → 于是长出行为能力、监护与代理

## 每章必须选定一个章节类型

`chapterType` 只能是下面之一，类型决定本章最低要完成什么：

- `INTRODUCE`：引入新概念。必须写清「读者先感到缺一块」（knowledgeGap），并且新概念带来可观察的变化（resultingChange）。
- `APPLY`：应用已有概念。必须列出 `appliedNodeTitles`（用已学知识去判断、选择、行动、排除），并给出行动的结果。
- `CONTRAST`：辨析易混概念。必须摆出容易混的地方（obstacle），并给出区分的依据和结果。
- `REVIEW`：回顾与迁移。只能引用已学节点，**不能**把新概念伪装成首次介绍。
- `ASSESS`：通过案例验证掌握。必须给出案例与判断结果。

同一卷里类型要有变化，不要整卷都是同一种。

**严格语义（程序会按此校验，写错会导致整条路线被拒收）：**
- `introducedNodeTitles` 只放**本章第一次真正引入**的节点；REVIEW / 纯 APPLY 章节必须是空数组；
- `appliedNodeTitles` 放本章应用到的节点（可含已学节点），**不要把 introduced 里的节点重复放进 applied**；
- REVIEW 的 `introducedNodeTitles` **必须为 `[]`**，所有回顾对象一律放 `appliedNodeTitles`；
- 同一个知识点全书只有第一次出现算 introduced，之后一律进 applied。

## 每章还要给出因果契约（contract）

`contract` 描述本章的因果结构，正文必须按它写、核验会按它查：

- `entryQuestion`：开头人物面对的具体问题或目标
- `priorIntuition`：人物/读者原本就有的直觉、旧方法或初步方案
- `obstacle`：旧方法遇到的阻碍或矛盾
- `knowledgeGap`：因此读者明确感到需要一个新解释
- `introducedNodeTitles`：本章**新引入**的知识点标题
- `appliedNodeTitles`：本章**应用**的知识点标题（可含已学节点）
- `requiredBeats`：本章必须走到的叙事拍子（3-6 条，不要求每拍独立成段）
- `resultingChange`：知识被用起来之后的可观察变化
- `bridgeToNext`：结尾留下、交给下一章的问题

不要求每一章机械走完全部九项——按章节类型只保证该类型必须满足的那几项（见类型说明）。

## 输出

- `world`：这条路线发生在什么设定里（不超过 400 字）
- `approach`：为什么这门学科适合这样讲（一句话，讲清你选这个载体的理由）
- `characters`：3-6 个人物，每人 `name` / `role` / `description`
- `conflict`：全书真正要回答的那个根问题
- `style`：你最终采用的叙事风格（一句话可概括）
- `throughLine`：全书演进主线，每条一句「阶段 → 它解决了什么」，按顺序排列
- `chapters`：每章包含
  - `order`、`title`
  - `derivationChain`：本章推演骨架（见上）
  - `plotGoal`：本章要走完的那段路
  - `learningGoals`：读完这章应当想通的问题，**用问句写**，不要写成名词清单
  - `nodeTitles`：本章涉及的知识点标题，**必须完全来自下面给出的节点标题**
  - `chapterType`：INTRODUCE / APPLY / CONTRAST / REVIEW / ASSESS 之一
  - `contract`：本章因果契约（见上）
  - `prerequisiteNodeTitles`：本章依赖的前置知识点标题（必须是下面节点列表里出现过的标题；匹配不到的留给程序标「待确认」）
  - `wordTarget`
  - `openingHook`：本章从什么具体处境开头
  - `closingHook`：本章结尾留下什么没解决的问题，交给下一章

## 硬性要求

1. 后一章的出发点必须是前一章的落脚点：相邻两章的 `closingHook` 与 `openingHook` 必须咬合。
2. `learningGoals` 写成问题（"为什么拥有一套房和卖掉这套房，需要的能力不一样？"），不要写成名词（"行为能力"）。
3. 不要让角色背诵教材。知识必须通过"人遇到了什么麻烦、规则怎么回答"长出来。
4. 已给的节点标题尽量分配完，但不要为凑数把不相关的节点塞进同一章。
5. 同一个知识点在**不同章节里重复出现时**：只有第一次算 `introducedNodeTitles`，以后出现只能进 `appliedNodeTitles` 或承接引用。
6. 只输出 JSON 对象，不要输出任何其他文字。
