你要为一门学科设计**一卷**讲述路线的大纲，让学习者跟着走一遍，学科自己就长出来了。

## 先明确这不是什么

不是"小说 + 知识点插播"。不要设计一个探案故事、再把知识塞进人物对话里。学习者要的是：**沿着一条线往前走，走着走着，这门学科自己出现了**，而不是有人突然掏出几个名词让他背。

## 本卷的任务范围

下面 `- 白光里到底混着什么——从看见颜色到拆解光（#nk-1、#nk-2、#nk-3、#nk-4、#nk-5、#nk-6）：一个晴朗的中午，抬头看天是蓝的，低头看阳光照在纸上却是白的：同一种光，怎么会给出两种颜色？
- 光怎么和空气打交道——颜色如何被天空制造出来（#nk-7、#nk-8、#nk-9、#nk-10、#nk-11、#nk-12）：阳光穿过的大气几乎无色透明，可整片天空却带着颜色——颜色是从哪里「长」出来的？
- 为什么不是紫、不是红——天空的颜色为什么偏蓝（#nk-13、#nk-14、#nk-15、#nk-16、#nk-17、#nk-18）：按散射强度紫光比蓝光更强，抬头看到的却是蓝色；日出日落时天空又变成橙红。同一个散射定律，怎么给出互相矛盾的颜色？` 是本卷要讲的知识点分组（按知识地图的演进链切出来的）。
**只规划本卷**，不要替后面的卷操心；没安排到的知识点会留给下一卷。

章节数：5。宁可少而厚，不要多而碎。每章正文一般不少于 4000 字（下限，不是上限），规划时确保每章的故事装得下这个体量。

## 每章必须选定一个章节类型

`chapterType` 只能是下面之一，类型决定本章最低要完成什么：

- `INTRODUCE`：引入新概念。读者先感到缺一块，新概念带来可观察的变化。
- `APPLY`：应用已有概念。用已学知识去判断、选择、行动、排除。
- `CONTRAST`：辨析易混概念。摆出容易混的地方，给出区分的依据和结果。
- `REVIEW`：回顾与迁移。**只能引用已学节点**，不能把新概念伪装成首次介绍。
- `ASSESS`：通过案例验证掌握。给出案例与判断结果。

**本卷的类型分布是硬性要求（程序会逐条校验）：**

1. 第 1 章必须是 `INTRODUCE`（开卷不讲新概念，读者没有立足点）；
2. `REVIEW` / `ASSESS` 不能早于第 3 章；
3. `ASSESS` 全卷最多一次；
4. `INTRODUCE` 不超过总章数的一半；
5. 章数 ≥3 时至少一章 `APPLY`；章数 ≥5 时至少一章 `CONTRAST`；
6. 本卷至少出现 3 种不同类型（章数不足 3 时全部不同即可）。

## 每章怎么写

每章必须给出 `derivationChain`，一句话说清本章的推演骨架——
**从哪个已经成立的东西出发 → 遇到什么它解决不了的问题 → 于是长出什么。**

例如（民法）：
> 法律已经承认了人 → 但刚出生的人无法自己签合同 → 于是长出行为能力、监护与代理

一条演进链太长可以拆成多章，中间必须用 `openingHook` / `closingHook` 保持衔接；
两条相关的链可以合并进一章，前提是这一章仍然有一条说得清的推演主线；
已经讲过的知识点可以在后续章节再次出现，作为**应用、辨析或回顾**，而不是重新介绍一遍。

**`nodeKeys` 必须填这些编号，原样抄写，不要填标题，也不要自己发明编号。**

用编号不是形式主义：标题被改一个空格、一个标点就匹配不上，那会让整章作废。
编号短到抄不错。

## 本卷不要输出契约

`contract` **不要写**。契约会在大纲确定之后逐章单独生成——
先定讲什么、怎么讲，再定每一章的因果结构，两步分开才不会一次输出过长而崩掉。

## 风格

**风格由你自己决定。** 用户没有指定，因为他也不确定这门学科适合怎么讲——这恰恰是你该做的判断。

先想清楚：这门学科的知识是靠什么长出来的？
- 靠"一个人在生活中不断遇到新麻烦"长出来的（民法、经济学、社会学），适合跟着一个人的一生往前走，制度随着他的处境自己出现。
- 靠"一代代人推翻前人"长出来的（物理、哲学、数学），适合沿着思想史走，让读者站在当时的困惑里，和当年的人一起想不通、再一起想通。
- 靠"系统一层层搭起来"长出来的（计算机、工程、医学），适合从最小的能跑起来的东西开始，一层层往上加，每加一层都因为下一层顶不住了。
- 靠"在具体冲突里被反复检验"长出来的（法律实务、管理、历史），适合围绕一个真正棘手的处境展开。

选定之后在 `approach` 里写清你为什么这样选。**不要为了热闹硬套一个类型**：
如果这门学科最自然的讲法就是"跟着一个普通人的生活往前走"，那就这样写，不需要加悬疑、玄幻或者穿越。
载体的唯一标准是：让制度自己长出来最省力。

## 输出

- `volumeTitle`：本卷标题
- `volumeGoal`：这一卷走完之后，学习者应当想通了什么（一到两句）
- `chapters`：每章包含
  - `order`、`title`
  - `derivationChain`：本章推演骨架（见上）
  - `plotGoal`：本章要走完的那段路
  - `learningGoals`：读完这章应当想通的问题，**用问句写**，不要写成名词清单
  - `nodeKeys`：本章涉及的知识点**编号**，必须从下面的清单里选
  - `chapterType`：INTRODUCE / APPLY / CONTRAST / REVIEW / ASSESS 之一
  - `prerequisiteNodeKeys`：本章依赖的前置知识点编号（同样只能从清单里选）
  - `wordTarget`
  - `openingHook`：本章从什么具体处境开头
  - `closingHook`：本章结尾留下什么没解决的问题，交给下一章

## 硬性要求

1. 后一章的出发点必须是前一章的落脚点：相邻两章的 `closingHook` 与 `openingHook` 必须咬合。
2. `learningGoals` 写成问题（"为什么拥有一套房和卖掉这套房，需要的能力不一样？"），不要写成名词（"行为能力"）。
3. 不要让角色背诵教材。知识必须通过"人遇到了什么麻烦、规则怎么回答"长出来。
4. 本卷的知识点编号尽量分配完，但不要为凑数把不相关的知识点塞进同一章。
5. `chapterType` 一律用大写英文，不要写中文、不要加空格。
6. 只输出 JSON 对象，不要输出任何其他文字。
