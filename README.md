# 知述（Zhishu）

把结构化知识转化为连续故事的 Android 学习工具。

## 产品定位

不是“小说生成器”，而是“故事化学习系统”。故事是主要入口，知识地图是导航，搜索是定位工具：

主题 → 知识主干 → 讲述路线 → 分章生成 → 事实核验 → **连续阅读**（知识点 ⇄ 知识地图 ⇄ 正文定位）

测验与间隔复习是可选辅助，默认不进主线（数据与页面全部保留，可在「我的」页开启）。

## 已实现功能（MVP）

- **学习工作台**：项目列表、继续阅读（按块恢复位置）、一键载入示例项目（民法继承案）
- **创建项目向导**：主题、基础水平、学习深度、故事类型、每日时长、目标天数，以及资料添加（粘贴文本 / 网页地址 / 文件选择）。全部资料解析成功后才在单个事务里落库，中途失败不留半成品项目
- **资料中心**：TXT / Markdown / PDF / URL 解析（解析与抓取都在 IO 线程），内容去重，资料删除
- **知识地图**：树形展示、展开/折叠、节点详情（来处/去处、定义、前置、易混淆、案例、来源），**「在故事里读它」可直接跳到对应章节的具体正文块**，确认标记、掌握度，并展示模型报告的资料缺口与资料冲突
- **故事大纲**：章节列表、状态流转、章节标题/剧情目标/知识点编辑、核验说明与失败重试入口
- **生成任务**：一章一个 WorkRequest，批量在入队时展开成串行链；**同一项目只允许一个生成会话**（项目级唯一名 + `KEEP`，连点不重复扣费）；**随时可取消**（状态条与前台通知都有取消，取消整条链）；真正调模型的 Worker 走前台长任务，进程重启后 WorkManager 接着跑剩下的章节
- **正文与测验解耦**：正文过核验就发布、就能读。出题失败只记在章节的 `quizState` 上，不阻塞阅读、不阻塞下一章、更不会为补几道题重写正文（可单独「重新生成自测」）
- **正文版本化**：每次生成写一个独立版本，只有核验通过才把 `chapters.activeVersionId` 原子切过去。重生成失败、核验不过或用户取消，**读者手里的正文一个字都不会变**；旧版本正文块一律保留（可追溯），阅读、搜索、知识点跳转与自测题只认当前版本。被新版本取代的旧正文记为 `ARCHIVED`（它成功过），只有从未通过核验的尝试记为 `ABANDONED`——两者混成一个值时，每次**成功**重生成都会被报成失败
- **来源与引用可追溯**：资料可填法域 / 生效时间 / 法律版本 / 文档版次；片段带页码、章节路径与段落序号（稳定锚点，不用字符偏移）；正文块与资料片段的引用关系单独成表，按 `versionId + blockId + chunkId` 绑定。模型给出的、对不上任何真实片段的引用**记为「未确认」而不是被丢掉**——丢掉会让那句需要出处的话变成没人管的断言，而阅读器还会显示「本段无引用」。阅读器每个正文块都有来源入口：资料名、页码/章节、版本与法域、原文摘录、是否来自用户资料、是否需要人工核对
- **分卷续讲**：首次只规划一卷 4~8 章，读完再按当前状态规划下一卷（`generateNextVolume`）。续卷只往后加章节，不改也不删已发布内容；续卷上下文只有累积状态 + 上一章当前版本的结尾 + 已讲/待讲知识点标题，不携带任何历史正文。已有已发布章节时**拒绝整本重新规划**
- **覆盖关系按 ID 记账**：「这个知识点讲过没讲过」看 `coveredNodeIds` 而不是标题。按标题记账的话，用户改一次知识点名字，讲过的内容就全变回「还没讲」，续卷把它们再排一遍。对不上任何现存知识点的旧标题标为「待确认」，既不硬猜也不算成未覆盖
- **阅读器**：`LazyColumn` 按块渲染（稳定 `key`，长章节不再一次性组合全文）、安静/密集模式、知识块高亮、**本章导览**（本章解决什么、学习目标、涉及知识点、关键结论可跳转）、知识点卡片可回跳知识地图、上下章导航、**阅读进度按「章节 + 正文块 + 块内偏移」保存**；正文换过版本时进度回到章首并给一次「本章正文已更新」的说明（只说一次，中性底色——正文更新是好事，不是出错）
- **知识搜索**：跨知识点、章节正文、资料原文搜索，走 FTS 倒排索引，**命中后定位到具体正文块并短暂高亮**
- **章节自测**：回忆题（自评）/ 判断题 / 案例题，放在章末「自测」按钮里由用户主动开启，不自动弹出、不阻塞下一章；答题记录持久化、掌握度一题只计一次
- **复习中心（可选）**：间隔复习（1/3/7/14/30 天）。默认关闭——关闭时不自动创建复习计划、首页不显示「今日复习」；在「我的 → 学习方式」开启后恢复完整节奏，已有数据不受影响
- **模型配置**：FAST / STORY / VERIFY 三种角色可分别配置兼容 OpenAI 接口的服务商（仅 https）；API Key 使用 Android Keystore 加密存储、密码方式输入，支持连通性测试
- **备份导入导出**：ZIP 格式（`formatVersion` 7），包含项目/资料/知识/章节/正文版本/引用关系/测验/进度，**绝不包含 API Key**；导入先整包校验再单事务写入，并有条目数/解压大小上限。旧备份（v1~v6）仍可导入——缺少的版本信息按「每章一个初始版本」补齐，缺少的分卷字段落在第一卷，缺少的引用表按正文块自己的 `sourceRefs` 重建（规则与 v9→v10 迁移逐字一致），导入不会把旧版本正文当成当前正文，也不会把「未确认引用」悄悄修成已确认

## AI 生成流程

1. 创建项目（无资料模式只填主题即可）
2. 「知识主干」→ 梳理这门学科的演进主干（一个概念从哪来、又引出什么）
3. 确认知识点后「讲述路线」→ 规划世界观、人物、章节推演链与知识点分配
4. 逐章生成 → 分章正文 + 事实核验 + 自测题
5. 阅读（安静/密集）→ 知识点跳知识地图 → 搜索定位回正文 → 继续下一章

## 构建与运行

环境要求：

- Android Studio（自带 JDK 21）
- Android SDK（本项目使用 `E:\engine\androidstudioSDK`，见 `local.properties`）

```powershell
# 编译 Debug APK
.\gradlew.bat :app:assembleDebug

# 单元测试（263 个，含真实 WorkManager 调度、Robolectric、Room 迁移、引用解析与 Compose UI 测试）
.\gradlew.bat :app:testDebugUnitTest

# Lint 检查
.\gradlew.bat :app:lintDebug
```

APK 输出：`app/build/outputs/apk/debug/app-debug.apk`

## 数据库

- 当前版本：10。Room schema 导出到 `app/schemas/`，v1→v2 一路到 v9→v10 都提供了非破坏性 `Migration`（不使用 `fallbackToDestructiveMigration`）。
  - v9→v10：`sources` 增加 `jurisdiction` / `effectiveFrom` / `legalVersion`；`source_chunks` 增加 `pageNumber` / `sectionPath` / `paragraphIndex`；`chapter_versions` 增加 `usedModelKnowledge`（按项目当时的知识模式回填）；新增 `citations` 表，并把现有 `chapter_blocks.sourceRefs` 全部搬进去（**含历史版本**）。对不上现存片段的引用记成 `UNCONFIRMED` 而不是丢掉；旧片段的页码与章节留空——它们是用当年那套不记位置的分块逻辑切出来的，硬填一个数字会让用户翻到错误的页码。
  - v8→v9：`chapter_versions` 的作废状态拆成 `ARCHIVED` / `ABANDONED`（有正文块且版本号比当前指针旧 → 归档，其余保持作废）；`chapters` / `chapter_versions` / `story_bibles` 增加 `coveredNodeIds`（按标题**唯一**匹配回填，重名或对不上的留空，不猜）；`reading_progress` 增加 `bodyUpdatedAt` / `progressNoticeShown`。
  - v7→v8：`chapters` 增加 `volumeIndex` / `volumeTitle` / `volumeGoal`，`story_bibles` 增加 `currentVolumeIndex`。旧数据全部落在第一卷，默认值即正确。
  - v6→v7：`chapters` 增加 `openingHook`，拆开 `carryOver` 的双重语义——它原来在未发布章节里装「开头钩子」、在已发布章节里装「结尾状态」，只能靠章节状态猜。迁移把这个猜法固化一次：未发布 → `openingHook`，已发布 → 当前版本的 `endingState`。`carryOver` 列保留，不再读写。
  - v5→v6：新增 `chapter_versions` 表，`chapters` 增加 `activeVersionId`，`chapter_blocks` / `quizzes` 增加 `versionId`。为每个现有章节建一个初始版本 `<章节id>-v1`，现有正文与自测题绑上去，正文可读的章节把指针指过去；一个正文块都不删。
  - v4→v5：`chapters` 增加 `quizState` / `quizNote`。正文发布不再依赖出题成功；历史上停在 `QUIZ_FAILED` 的章节被扶正成「正文已发布 + 测验失败」，原失败说明搬进 `quizNote`，数据不丢。
  - v3→v4：`reading_progress` 增加 `blockOffset`。阅读进度改为「章节 + 正文块 + 块内偏移」；旧的 `charOffset`（整章滚动像素）保留但不再写入——它换机型或字号就失效，也和搜索用的字符位置不是同一坐标系。
- 正文与资料片段各有一张 FTS4 索引表。中文子串检索靠**字符二元组**分词实现（FTS 默认分词器会把连续中文当成一个 token，FTS5 的 trigram 分词器要求 SQLite 3.34+，在 minSdk 26 上不可用）。

## 首次使用建议

1. 安装后进入「学习」页，点击「载入示例项目」，可直接体验知识地图、阅读器、测验与复习全流程
2. 体验完成后在「我的」页配置模型（三个角色分别填接口地址、模型名、API Key）
3. 创建自己的学习项目，粘贴教材/法条/讲义内容，开始生成专属故事

## 已知限制

- PDF 仅支持可复制文字的版本，扫描版 PDF 需要 OCR（标记为“扫描版”）
- v10 之前导入的资料片段没有页码与章节路径（当年的分块逻辑没记位置，无从倒推），来源只能定位到「第几段」；重新导入一次同一份资料即可拿到完整定位
- 生成依赖网络与已配置的模型；核验环节会提示差异，需人工确认
- 引用「未确认」只说明我们没能把模型给出的出处对上真实片段，不代表那句内容一定错——但它值得你自己核对一次
- 模型接口与网页抓取只允许 https；应用已关闭系统备份（`allowBackup=false`），因为 API Key 绑定本机 Keystore，跨设备恢复无法解密
- 中文全文检索基于二元组，单字查询走前缀匹配，可能带回较多结果
