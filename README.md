# 知述（Zhishu）

把结构化知识转化为连续故事的 Android 学习工具。

## 产品定位

不是“小说生成器”，而是“故事化学习系统”。故事是主要入口，知识地图是导航，搜索是定位工具：

主题 → 知识主干 → 讲述路线 → 分章生成 → 事实核验 → **连续阅读**（知识点 ⇄ 知识地图 ⇄ 正文定位）

测验与间隔复习是可选辅助，默认不进主线（数据与页面全部保留，可在「我的」页开启）。

## 已实现功能（MVP）

- **学习工作台**：项目列表（竖排书架式 3 列封面，2:3 标准书比例、衬线书名、底部阅读进度条；继续阅读横幅 / 知识页卡片 / 空书架插画统一同一套迷你封面）、继续阅读（按块恢复位置）、一键载入示例项目（民法继承案）；写过内容又超两周没备份时书架顶部出现一条可关闭的温和提醒，直达备份入口
- **创建项目向导**：主题、基础水平、学习深度、故事类型、每日时长、目标天数，以及资料添加（粘贴文本 / 网页地址 / 文件选择）。全部资料解析成功后才在单个事务里落库，中途失败不留半成品项目
- **资料中心**：TXT / Markdown / PDF / URL 解析（解析与抓取都在 IO 线程；TXT 先按 UTF-8 严格解码、失败回退 GB18030，非 UTF-8 文件不再乱码），内容去重，资料删除
- **知识地图**：树形展示、展开/折叠、节点详情（来处/去处、定义、前置、易混淆、案例、来源），**「在故事里读它」可直接跳到对应章节的具体正文块**，确认标记、掌握度，并展示模型报告的资料缺口与资料冲突。**分步生成**：骨架先行 → 用户自选逐条展开或全部展开，进度卡实时显示每条链状态；未完成批次给「继续展开」入口（只补没做完的部分），与「重新梳理」（开新批次）分开
- **故事大纲**：章节列表、状态流转、章节标题/剧情目标/知识点编辑、核验说明与失败重试入口
- **生成任务**：一章一个 WorkRequest，批量在入队时展开成串行链；**同一项目只允许一个生成会话**（项目级唯一名 + `KEEP`，连点不重复扣费）；**随时可取消**（状态条与前台通知都有取消，取消整条链）；真正调模型的 Worker 走前台长任务，进程重启后 WorkManager 接着跑剩下的章节；生成状态条实时显示「已用 X tokens」，完成通知带本次生成总用量，完成说明附会话累计消耗
- **正文与测验解耦**：正文过核验就发布、就能读。出题失败只记在章节的 `quizState` 上，不阻塞阅读、不阻塞下一章、更不会为补几道题重写正文（可单独「重新生成自测」）
- **正文版本化**：每次生成写一个独立版本，只有核验通过才把 `chapters.activeVersionId` 原子切过去。重生成失败、核验不过或用户取消，**读者手里的正文一个字都不会变**；旧版本正文块一律保留（可追溯），阅读、搜索、知识点跳转与自测题只认当前版本。被新版本取代的旧正文记为 `ARCHIVED`（它成功过），只有从未通过核验的尝试记为 `ABANDONED`——两者混成一个值时，每次**成功**重生成都会被报成失败
- **来源与引用可追溯**：资料可填法域 / 生效时间 / 法律版本 / 文档版次；片段带页码、章节路径与段落序号（稳定锚点，不用字符偏移）；正文块与资料片段的引用关系单独成表，按 `versionId + blockId + chunkId` 绑定。模型给出的、对不上任何真实片段的引用**记为「未确认」而不是被丢掉**——丢掉会让那句需要出处的话变成没人管的断言，而阅读器还会显示「本段无引用」。阅读器每个正文块都有来源入口：资料名、页码/章节、版本与法域、原文摘录、是否来自用户资料、是否需要人工核对
- **核验问题可操作化**：核验结果不再是一段拼起来的文字，而是逐条记录（类型、说明、建议改法、相关来源、出问题的正文块），一条不丢。用户可以勾选出问题的段落**只重写这几段**：从当前正文派生草稿版本 → 复制没问题的块 → 只重写选中的块 → **全章**重新核验 → 通过后才原子切换 `activeVersionId`。失败、取消或改完仍有问题时草稿作废，**读者手里的正文一个字都不会变**。定位不到具体段落的问题如实说「只能整章重新生成」，不给一个点了没用的按钮；「已修」只由「重写 → 重新核验 → 问题没再出现」推出来，用户能做的只有「我看过了，不用改」
- **核验自动处理（默认开，「我的 → 学习方式」可关）**：核验发现问题不再立刻打断用户——先自动局部重写（最多两轮，每轮仍限 6 段护栏，`reverifyChapter` 同样接入），修得掉就直接发布；两轮后仍未解决的**文风类**问题自动标记「不用改」（它不是事实错误，反复弹只会挡住正文），**事实类**问题（编造出处、自相矛盾等）一律保留，完成后通知里汇总「自动修复 N 章，M 章剩 X 个问题待看」。项目页的待复核入口与可信度中心相应收敛成一行小卡，点开才看清单
- **阅读可信度呈现**：读者要回答的是「我眼前这一章、这一段有多可信」，所以五种处境分开说，不混成一句「未确认」——**已确认来源**（能点开原文）、**未确认来源**（模型给了出处但对不上，可能是它自己凑的）、**来源已删除**（当初确实有依据，那份资料被删了，重新导入即可恢复定位）、**法域/生效范围限制**（这条规则未必在你的处境下成立）、**旧数据只能定位到片段**（v10 之前导入的资料没有页码，是我们定位能力不够、不是内容有问题）。删资料时会把资料标题抄进引用，否则「引用的资料已被删除」等于什么都没说，用户既不知道该重新导入哪份，也没法判断那一段还站不站得住。
  - 章节级来源摘要（阅读器顶栏一个入口，默认折叠）：用户资料份数、可定位引用、未确认与已删来源、是否含 AI 自备知识、待核对的核验问题（其中几条能定位到具体段落）、法域与生效时间。**全部数字只算当前 `activeVersionId`**——按全部版本数的话，一章每重生成一次「本章有几处来源」就翻一倍，而读者眼前的正文并没有变长
  - 块级可信度面板：关联来源、页码/章节/段落序号、原文片段、来源是否还在、引用是否已确认、是否含模型自备知识，以及这一段的核验问题与处理状态。安静模式下**只有出处没对上或有待处理问题时才露出入口**，「这一段有 3 处正常来源」不该在读故事时反复打断视线；密集模式给完整入口
  - 正文 ⇄ 资料双向回跳：正文块打开资料详情并自动滚到对应片段；资料页反过来列出「这一段被当前正文哪几块引用」，点回阅读器对应章节与正文块。两个方向都只认当前版本——历史版本的引用一条都不删，但混进来会让用户点到一段已经不存在的正文
  - 未核实内容筛选（可信度中心）：全书的未确认引用、已删来源与待处理问题一页看完，按未确认 / 已删除 / 待核对筛选。定位不到具体段落的问题照样列出并如实说「只能整章重新生成」，不给一个点了没用的重写按钮
- **分卷续讲**：首次只规划一卷 4~8 章，读完再按当前状态规划下一卷（`generateNextVolume`）。续卷只往后加章节，不改也不删已发布内容；续卷上下文只有累积状态 + 上一章当前版本的结尾 + 已讲/待讲知识点标题，不携带任何历史正文。已有已发布章节时**拒绝整本重新规划**
- **覆盖关系按 ID 记账**：「这个知识点讲过没讲过」看 `coveredNodeIds` 而不是标题。按标题记账的话，用户改一次知识点名字，讲过的内容就全变回「还没讲」，续卷把它们再排一遍。对不上任何现存知识点的旧标题标为「待确认」，既不硬猜也不算成未覆盖
- **阅读器**：`LazyColumn` 按块渲染（稳定 `key`，长章节不再一次性组合全文）、安静/密集模式、知识块高亮、**本章导览**（本章解决什么、学习目标、涉及知识点、关键结论可跳转）、知识点卡片可回跳知识地图、上下章导航、**阅读进度按「章节 + 正文块 + 块内偏移」保存**；正文换过版本时进度回到章首并给一次「本章正文已更新」的说明（只说一次，中性底色——正文更新是好事，不是出错）；读到当前卷最后一章且下一卷尚未规划时，章末出现「规划下一卷」入口直达讲述路线——分不清「讲完了」还是「还没写」的状态不再无出口
- **知识搜索**：跨知识点、章节正文、资料原文搜索，走 FTS 倒排索引，**命中后定位到具体正文块并短暂高亮**
- **章节自测**：回忆题（自评）/ 判断题 / 案例题，放在章末「自测」按钮里由用户主动开启，不自动弹出、不阻塞下一章；答题记录持久化、掌握度一题只计一次
- **复习中心（可选）**：间隔复习（1/3/7/14/30 天）。默认关闭——关闭时不自动创建复习计划、首页不显示「今日复习」；在「我的 → 学习方式」开启后恢复完整节奏，已有数据不受影响
- **模型配置**：FAST / STORY / VERIFY 三种角色可分别配置兼容 OpenAI 接口的服务商（仅 https）；API Key 使用 Android Keystore 加密存储、密码方式输入，支持连通性测试。**配置前置引导**：空书架页与创建项目页检测到缺角色时显示「还差一步」提示卡，一键开讲 / 梳理主干点击时直接拦截并给「去配置」直达，不再等入队后才报错
- **备份导入导出**：ZIP 格式（`formatVersion` 8），包含项目/资料/知识/章节/正文版本/引用关系/核验问题/测验/进度，**绝不包含 API Key**；导出成功记时间戳，超 14 天且有已发布章节时书架顶部温和提醒一次；导入先整包校验再单事务写入，并有条目数/解压大小上限。4C 新增的字段靠序列化默认值向后兼容，因此格式号不变——升一位会让上一版应用拒绝导入它自己完全读得懂的备份。旧备份（v1~v7）仍可导入——缺少的版本信息按「每章一个初始版本」补齐，缺少的分卷字段落在第一卷，缺少的引用表按正文块自己的 `sourceRefs` 重建（规则与 v9→v10 迁移逐字一致），缺少的核验问题表就是空的（旧数据只有一句拼起来的说明，没有 blockId 也没有类型，回填只会造出一批假记录），导入不会把旧版本正文当成当前正文，也不会把「未确认引用」悄悄修成已确认，更不会把用户判定「不用改」的问题重置成待处理。**「来源已删除」这个状态也原样带过去**：它和「未确认」在库里的差别只有一个状态值，重算会把「当初有依据、资料被删了」说成「模型给的出处一开始就没对上」，被删资料的名字还会一起丢掉；反过来，如果导入时那个片段又在了（用户重新导入过同一份资料），就回到已确认并清掉标题——继续说「资料已删除」是在陈述一件已经不成立的事

## AI 生成流程

1. 创建项目（无资料模式只填主题即可）
2. 「知识主干」→ **骨架先行**：先只花一次小调用列出演进链结构，用户看过之后自己选节奏——「展开下一条链」逐条推进（每条一确认），或「全部展开」一口气跑完（一键开讲链自动走全部）。链数由学科规模决定（小话题 2-4 条、大学科 10 条以上都可以），不设固定区间
3. 确认知识点后「讲述路线」→ 规划世界观、人物、章节推演链与知识点分配
4. 逐章生成 → 分章正文 + 事实核验 + 自测题
5. 阅读（安静/密集）→ 知识点跳知识地图 → 搜索定位回正文 → 继续下一章

### 知识主干的失败处理与消耗控制

- **单链失败不中止整批**：某条演进链展开失败只标记该链（地图页进度卡显示「几条失败」），其余链照常展开；点「重试失败链并继续」只补失败的部分，已花钱展开的内容不作废重来
- **节点标识用短序号**：`nk-1`、`nk-2`…（原来是 40 位 UUID，要求模型逐字符回传，抄错一位节点就被静默丢弃）；就算标识没对上，还有骨架标题兜底匹配
- **截断 JSON 本地补全**：模型输出在长度上限处被切断时，解码层先在本地剪裁补全（免费、即时，救回前面所有完整成员），救不回来才走模型修复——不再把损坏 JSON 全文重发一遍按 token 双倍计费
- **链展开输出限长**：每个字段有明确长度上限（定义 ≤80 字、来处/去处各一句话、清单各 ≤3 条），输出小一半，截断概率大降
- **资料检索用子词匹配**：中文长标题整词几乎不会逐字出现在原文里，改按二元组子词打分选片段——命中 relevant 片段而不是每条链都退化成「项目前 20 条」
- **审计去原文**：全局审计只吃节点摘要 + 资料清单（原来一次塞全项目 50 条×500 字原文，2-3 万 token）；审计失败按软失败收尾——地图内容完整可用，gaps 落一条说明，不再报「生成失败」逼用户重试

## 启动健壮性

「一打开就闪退」多半不是代码 bug，而是设备态异常（升级迁移时断电、进程被杀在写盘中途导致库文件损坏等），此前这些异常会顺着首页首个查询的协程冒成未捕获异常，直接杀死进程，且每次启动如此。现在有三层防御：

1. **启动预热 + 损坏自愈**：Application 启动后台线程打开数据库（迁移与首帧并行，顺带加快冷启动）。打不开时把损坏文件连同 wal/shm 改名保留为 `zhishu.db.corrupt-<时间戳>`（现场不删，可手动找回），原位置重建空库——APP 至少能打开。
2. **ViewModel 协程兜底**：首页的后台任务失败先延迟重试一次（覆盖自愈尚未完成的窗口），仍失败只记日志；项目列表 Flow 订阅失败会等待重订而不是炸掉 Compose 组合。
3. **崩溃日志落盘**：任何未捕获异常写入应用私有目录 `files/crash/`（保留最近 5 份），下次诊断不再靠猜。

注：自愈重建的是空库，历史内容以备份文件形式留在原地；定期用「我的 → 备份导出」可以进一步降低损失。

## 数据库

- 当前版本：15。Room schema 导出到 `app/schemas/`，v1→v2 一路到 v14→v15 都提供了非破坏性 `Migration`（不使用 `fallbackToDestructiveMigration`）。
  - v14→v15：`chapters` 增加 `chapterType` / `contractJson`（章节因果契约，路线规划生成、正文按契约写、核验逐项检查；空串 = 旧数据未生成契约，读取方如实显示「未生成因果契约」，不伪造）。
  - v13→v14：`knowledge_nodes` 增加 `batchId`、`knowledge_map_batches` 增加 `active`——重新生成知识地图不再预先删旧图：新批次节点先落库但不生效，整批成功后事务切换，失败时旧地图完好。
  - v12→v13：知识地图分批生成（骨架 → 逐链展开 → 全局审计）。`knowledge_nodes` 增加 `nodeKey`（稳定标识，标题只做显示）与 `generateStatus`（旧数据一律 COMPLETED）；新增 `knowledge_map_batches` 批次状态表（过程状态，不随备份导出）。
  - v11→v12：`citations` 增加 `lostSourceTitle`，并启用 `SOURCE_DELETED` 状态（4C）。删资料时在**同一个事务里、`sources` 那一行还在的时候**把标题抄进引用——删完就查不到了，而「引用的资料已被删除」不说是哪一份，用户既没法判断那一段还站不站得住，也不知道该重新导入哪一份。**存量 `UNCONFIRMED` 一律不回填成 `SOURCE_DELETED`**：一条已经降级过的引用和一条从没对上的引用在旧库里没有任何区别，无从判断；全判成「资料已删除」会把模型编的出处说成用户自己的操作，那比说得保守一点糟得多。新的删除操作从这一版起分得清。
  - v10→v11：新增 `verification_issues` 表（核验问题逐条记录）；`chapter_versions` 增加 `derivedFromVersionId` / `rewrittenBlockIds`（局部重写的来源版本与改动块）。**旧的核验说明不回填成问题记录**——那段文字没有 blockId 也没有原始类型，而且很可能早被 `take(5)` 截断过，回填出来的「本章还有 3 个问题」从第一天起就不可信；它原样留在 `chapters.verificationNote` 里继续显示，新表从下一次核验开始有数据。
  - v9→v10：`sources` 增加 `jurisdiction` / `effectiveFrom` / `legalVersion`；`source_chunks` 增加 `pageNumber` / `sectionPath` / `paragraphIndex`；`chapter_versions` 增加 `usedModelKnowledge`（按项目当时的知识模式回填）；新增 `citations` 表，并把现有 `chapter_blocks.sourceRefs` 全部搬进去（**含历史版本**）。对不上现存片段的引用记成 `UNCONFIRMED` 而不是丢掉；旧片段的页码与章节留空——它们是用当年那套不记位置的分块逻辑切出来的，硬填一个数字会让用户翻到错误的页码。
  - v8→v9：`chapter_versions` 的作废状态拆成 `ARCHIVED` / `ABANDONED`（有正文块且版本号比当前指针旧 → 归档，其余保持作废）；`chapters` / `chapter_versions` / `story_bibles` 增加 `coveredNodeIds`（按标题**唯一**匹配回填，重名或对不上的留空，不猜）；`reading_progress` 增加 `bodyUpdatedAt` / `progressNoticeShown`。
  - v7→v8：`chapters` 增加 `volumeIndex` / `volumeTitle` / `volumeGoal`，`story_bibles` 增加 `currentVolumeIndex`。旧数据全部落在第一卷，默认值即正确。
  - v6→v7：`chapters` 增加 `openingHook`，拆开 `carryOver` 的双重语义——它原来在未发布章节里装「开头钩子」、在已发布章节里装「结尾状态」，只能靠章节状态猜。迁移把这个猜法固化一次：未发布 → `openingHook`，已发布 → 当前版本的 `endingState`。`carryOver` 列保留，不再读写。
  - v5→v6：新增 `chapter_versions` 表，`chapters` 增加 `activeVersionId`，`chapter_blocks` / `quizzes` 增加 `versionId`。为每个现有章节建一个初始版本 `<章节id>-v1`，现有正文与自测题绑上去，正文可读的章节把指针指过去；一个正文块都不删。
  - v4→v5：`chapters` 增加 `quizState` / `quizNote`。正文发布不再依赖出题成功；历史上停在 `QUIZ_FAILED` 的章节被扶正成「正文已发布 + 测验失败」，原失败说明搬进 `quizNote`，数据不丢。
  - v3→v4：`reading_progress` 增加 `blockOffset`。阅读进度改为「章节 + 正文块 + 块内偏移」；旧的 `charOffset`（整章滚动像素）保留但不再写入——它换机型或字号就失效，也和搜索用的字符位置不是同一坐标系。
- 正文与资料片段各有一张 FTS4 索引表。中文子串检索靠**字符二元组**分词实现（FTS 默认分词器会把连续中文当成一个 token，FTS5 的 trigram 分词器要求 SQLite 3.34+，在 minSdk 26 上不可用）。

## 首次使用建议

1. 安装后进入「学习」页，点击「载入示例项目」，可直接体验知识地图、阅读器、测验与复习全流程
2. 体验完成后在「我的」页配置模型（三个角色分别填接口地址、模型名、API Key）
3. 创建自己的学习项目，粘贴教材/法条/讲义内容，开始生成专属故事

## 已知限制

- PDF 仅支持可复制文字的版本，扫描版 PDF 需要 OCR（标记为“扫描版”）
- v10 之前导入的资料片段没有页码与章节路径（当年的分块逻辑没记位置，无从倒推），来源只能定位到「第几段」；重新导入一次同一份资料即可拿到完整定位
- 生成依赖网络与已配置的模型。核验自动处理（默认开）只自动放过文风类问题；事实类问题仍会标成「待复核」等用户确认——这是刻意保留的人工闸门，不是缺陷
- 引用「未确认」只说明我们没能把模型给出的出处对上真实片段，不代表那句内容一定错——但它值得你自己核对一次
- v11 之前删资料留下的引用只会显示成「未确认」，看不出是「资料被删了」还是「模型给的出处没对上」。旧库里这两种情况没有任何区别，硬判会把模型编的出处说成你自己删了资料；从 v12 起的删除操作分得清
- 阅读器的章节摘要与块级面板只统计当前正文版本。旧版本的引用与核验问题都完整保留在库里，但没有面向用户的历史版本浏览入口，所以那些数字暂时只能从当前这一版看到
- v11 之前的核验问题只留下一句拼起来的说明（没有 blockId、没有类型），所以老章节看不到逐条问题清单、也用不了「只重写这几段」；重新生成或重新核验一次即可获得完整清单
- 局部重写只改选中的段落，但发布前会做一次**全章**核验，因此它省下的是重写正文的成本，不是核验的成本；核验没通过时那次修改不会发布，正文仍是原来那一版
- 模型接口与网页抓取只允许 https；应用已关闭系统备份（`allowBackup=false`），因为 API Key 绑定本机 Keystore，跨设备恢复无法解密
- 中文全文检索基于二元组，单字查询走前缀匹配，可能带回较多结果
