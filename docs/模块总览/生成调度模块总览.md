# 生成调度模块总览

## 模块职责（一句话）

把用户点下的每一次「生成」变成一条 **WorkManager 串行链**：同一项目同时只有一个会话（不重复扣费）、一章一个 WorkRequest（断点续跑）、入队即建立前台保活（后台不被冻结）、全程可取消、自动闭环能自己续订下一步。

## 运作流程（从按下按钮到会话结束）

1. **入队**：界面调用 `GenerationEnqueuer`（如 `knowledgeMap` / `generateNextVolume` / 批量章节）。它做四件事：
   - 先查 `isActive`（该项目的唯一链上还有没有 ENQUEUED/RUNNING/BLOCKED 的工作）——已在跑就直接返回 `AlreadyRunning`，连点不重复扣费；
   - 以 `GenerationWorker.uniqueWorkName(projectId)` 项目级唯一名 + `ExistingWorkPolicy.KEEP` 排队，防重复的保险在调度层，不靠按钮禁用；
   - 把批量在**入队时**展开成一章一个 `OneTimeWorkRequest`，用 `WorkContinuation` 串成链（章节顺序有依赖：滚动记忆要上一章的结果）；
   - 调 `GenerationKeeperService.start()` 在前台时机一次性建立保活服务。
2. **保活**（`GenerationKeeperService`，前台 dataSync 服务）：入队永远发生在用户点按钮时（前台），服务此刻 `startForeground`；此后整个会话期间进程持有前台服务，链上每个 Worker 都在受保护状态跑。服务为**每个在保项目**挂一个观察器盯它的唯一链 WorkInfo（2026-10-27 起，原来是单 projectId 变量，两本书同时生成会互相覆盖）；某条链全部工作终态就撤观察，全部链收尾才 `stopSelf`。看门狗 6 小时（对齐 dataSync 前台服务在 Android 15 的单次上限），观察器失效时兜底退场。
3. **执行**（`GenerationWorker`，CoroutineWorker）：按 `inputData` 里的 `GenerationStage` 分派——`KNOWLEDGE_MAP`（骨架/逐链/审计，进度细粒度上报）、`STORY_BIBLE`、`SINGLE_CHAPTER`/`FIRST_CHAPTER`（转 `PipelineService.generateChapter`）、`ADVANCE`（不调模型，查库决定下一步）、`PLAN_NEXT_VOLUME`、`SUMMARY`（链尾总结：通知里报本次与累计 token）。缺模型配置时在调用前就失败并给出可读原因。每阶段用量并入会话账本（进程内存，进程被杀清零，通知里说「约」）。
4. **前台化与重试**：Worker 每到阶段边界尝试 `setForeground`（带取消按钮的进度通知）。Android 12+ 后台时机被拒时生成本身照跑，`ForegroundKeeper` 每 30 秒重试一次——用户切回 app 后最多一个周期保护自动补上。
5. **自动闭环**（`ADVANCE`）：`decideAdvance(autoOn, blocking, targets, pending)` 纯函数产出 `AdvanceDecision`（StoppedBySwitch / ContinueCurrentVolume / PlanNextVolume / PausedForUser / MainLineDone），Worker 据此 `APPEND` 新工作到同一条唯一链尾部或刹车。契约卡死的死角会发「到讲述路线重试契约」的指引通知。
6. **通知**（`GenerationNotifier`）：三类通知 ID **按项目哈希分区分配**（2026-10-27 起；原来进度 4101 / 保活 4102 是固定值，两本书同时生成会互相覆盖，前台服务结束撤通知还会撤掉别家的）。进度通知多章串行复用同一条；保活通知与进度通知分开 ID（共用会被 WorkManager 撤通知时连坐）；结果通知一次会话一条，取消不发。通知权限被拒时全部安静降级。
7. **取消**：通知上的「取消」按钮落到 `CancelGenerationReceiver` → `GenerationScheduler.cancel` 取消**整条项目唯一链**（只取消当前 Worker 的话后面几章会接着跑接着扣费），并撤该项目进度通知。`GenerationEnqueuer.cancel` 是 UI 共用的同一入口。

## 入口文件清单

| 文件 | 干什么 |
| --- | --- |
| `app/src/main/java/com/example/zhishu/worker/GenerationEnqueuer.kt` | 入队：唯一名 + KEEP 防重复、批量展开成串行链、自动续订入口（appendAutoChunk / appendVolumePlan） |
| `app/src/main/java/com/example/zhishu/worker/GenerationWorker.kt` | CoroutineWorker 主体：按 Stage 分派、缺配置早失败、失败退避重试、用量记账 |
| `app/src/main/java/com/example/zhishu/worker/GenerationStage.kt` | 阶段枚举（一个 WorkRequest 一件事） |
| `app/src/main/java/com/example/zhishu/worker/GenerationKeeperService.kt` | 前台保活服务：入队即 startForeground，多项目观察器表，全链收尾才退场 |
| `app/src/main/java/com/example/zhishu/worker/ForegroundKeeper.kt` | 前台化被拒后的 30 秒定时重试循环 |
| `app/src/main/java/com/example/zhishu/worker/GenerationNotifier.kt` | 三类通知（进度/保活/结果），ID 按项目分区，权限拒绝安静降级 |
| `app/src/main/java/com/example/zhishu/worker/CancelGenerationReceiver.kt` | 通知取消按钮落点 + `GenerationScheduler` 薄封装 |
| `app/src/main/java/com/example/zhishu/worker/AdvanceDecision.kt` | 自动闭环纯决策函数（纯 JVM 可测） |

## 对外接口 / 被谁调用

- `GenerationEnqueuer.*`：项目详情页（逐章/批量生成）、知识地图页（梳理主干）、讲述路线页（规划）、一键开讲、续卷入口。
- `GenerationEnqueuer.isActive`：UI 判断「正在生成」状态条。
- `GenerationEnqueuer.cancel` / `GenerationScheduler`：UI 取消按钮、通知取消按钮。
- `GenerationKeeperService.start`：仅 `GenerationEnqueuer` 入队路径调用（必须前台时机）。

## 依赖的上游模块

- 章节生成模块（`PipelineService`）：`SINGLE_CHAPTER`/`FIRST_CHAPTER`/`PLAN_NEXT_VOLUME` 的实际生成工作。见 [章节生成模块总览](章节生成模块总览.md)。
- 模型调用模块（`GenerationLog`）：失败留痕。
- 数据层：projectRepository / chapterRepository / learningPrefs（自动闭环开关与用量）。
- WorkManager：链调度、退避重试、进程重启续跑。

## 关键数据结构

- `GenerationStage`：KNOWLEDGE_MAP / STORY_BIBLE / SINGLE_CHAPTER / FIRST_CHAPTER / ADVANCE / PLAN_NEXT_VOLUME / SUMMARY。
- `EnqueueResult`：Started（排入，stageCount）/ AlreadyRunning / Nothing。
- `AdvanceDecision`：自动闭环五态（见文件头注释，每支都写明存在理由）。
- 项目级唯一链：`GenerationWorker.uniqueWorkName(projectId)`，`KEEP` 策略；续订用 `APPEND_OR_REPLACE` 追加到同一条链。
- 通知 ID 三分区（各 8192 槽，槽=projectId.hashCode() 截 13 位）：进度 410_100+、保活 420_100+、结果 430_100+。

## 已知坑与约束

- **保活服务只能在入队时启动**（前台时机）；后台启动前台服务在 Android 12+ 会被拒——这就是它存在的原因，别试图改成按需启动。
- **通知 ID 冲突面**：8192 槽哈希，两项目碰撞概率约 0.01%，后果只是通知互盖，无害。改区间时三类基底必须互不重叠。
- **多项目并行的边界**：`GenerationWorker` 的会话 token 账本（`sessionTokenUsage`）在进程内存里，进程被杀清零；通知里已按「约」口径。
- 观察器看到**空 WorkInfo 列表**不等于链被取消——取消后唯一名下是全部 CANCELLED（isFinished=true）照样退场；空列表只发生在唯一名从未有过工作。
- 自动续订先挂新工作再结束当前 Worker，观察器不会在续订间隙看到「暂时全完成」——改这个顺序会造成保活提前退场。
