# 应用自更新模块总览

## 模块职责

一句话：让 App 自己发现并安装新版本——设置页点「检查更新」（或启动时静默查一次）→ 弹窗显示更新说明 → 流式下载 APK → 唤起系统安装器覆盖安装，全程不用连电脑。

## 运作流程

**发新版一侧（云端，全自动）**：往 GitHub 仓库 `Lwb1397111398/Zhishu` 的 `main` 分支推一次代码 → GitHub Actions 按 `.github/workflows/build-release.yml` 自动跑两个 job：**先跑质量闸（test job）——`lintDebug` + 全量单元测试 `testDebugUnitTest`（2026-10-27 加，此前只构建不把关）**，过了才跑 release job：全量检出代码（`fetch-depth: 0`，因为版本号要数提交）→ Temurin JDK 17 → `./gradlew assembleRelease` → 把 APK 以 `Zhishu-latest.apk` 为名发布到仓库的 `latest` Release。Release 说明第一行是 HTML 注释 `<!-- zhishu-update versionCode=38 versionName=0.1.38 -->`——GitHub 页面上看不见，但 App 靠正则解析它拿版本号。质量闸失败时 release 不执行——坏版本发不出去，也就不会经自更新推到手机。

**版本号从哪来**：`app/build.gradle.kts` 里 `versionCode = git rev-list --count HEAD`（第 38 号提交构建出来就是 versionCode=38），`versionName = "0.1.38"`。本机和云端对同一个提交算出同一个号，每推一次自动 +1，App 只比较这个号判断有无新版本。

**签名从哪来**：`keystore/app.keystore` 是本机调试钥匙（`~/.android/debug.keystore`）的副本，直接提交进仓库，debug 和 release 两个构建类型都锁它。所以手机上已装的包、自己电脑构建的包、云端构建的包，签名指纹完全一致，覆盖安装不会被系统拒绝。

**查更新（App 端）**：`UpdateChecker.fetchLatest()` 用 `HttpURLConnection` GET `https://api.github.com/repos/Lwb1397111398/Zhishu/releases/latest`，带 `User-Agent: zhishu-app` 头（GitHub 强制要求，缺了 403）。仓库公开，匿名可查，不需要任何令牌。从返回 JSON 里解析：`body` 字段用正则抓 versionCode/versionName，`assets` 数组找第一个 `.apk` 拿下载地址和文件大小。**远端 versionCode 大于本机 `BuildConfig.VERSION_CODE` 才算有新版本**；404 = 还没发布过版本。

**下载**：`UpdateChecker.downloadApk()` 流式下载，64KB 缓冲边下边回调进度百分比。先写 `cacheDir/updates/update-38.apk.part` 临时文件 → 下载完核对字节数与 Content-Length 一致 → 改名为正式文件。中断不会留下半截包冒充完整包；同版本完整文件已存在（长度一致）直接复用不重下。

**安装**：`UpdateInstaller.install()` 经 FileProvider（authority `com.example.zhishu.update`，只开放 `cache/updates/` 子目录）把 APK 转成 `content://` URI，`ACTION_INSTALL_PACKAGE` 唤起系统安装器。Android 8+ 还需要「安装未知应用」授权：没授权时先跳系统开关页（`ACTION_MANAGE_UNKNOWN_APP_SOURCES`），用户打开后回来再点一次「安装更新」。

**界面接线**：`UpdateViewModel` 由根导航 `ZhishuRoot` 顶层持有一份（不是设置页私有）——启动时 `autoCheckIfNeeded()` 静默检查（24 小时节流，间隔存在 `LearningPrefs`），发现新版本弹 `UpdateDialog`，任何页面都能弹；设置页的「检查更新」按钮、状态行、自动检查开关都读写同一个 ViewModel。

## 入口文件清单

- `app/src/main/java/com/example/zhishu/data/update/UpdateChecker.kt` —— 查版本 + 下载（纯 JVM，可单测）
- `app/src/main/java/com/example/zhishu/data/update/UpdateInstaller.kt` —— FileProvider + 唤起系统安装器
- `app/src/main/java/com/example/zhishu/ui/screens/UpdateViewModel.kt` —— 状态机（检查/下载/安装/开关）
- `app/src/main/java/com/example/zhishu/ui/screens/UpdateDialog.kt` —— 更新弹窗（进度、错误、重试）
- `app/src/main/java/com/example/zhishu/ui/screens/SettingsScreen.kt` —— `AppUpdateSection` 设置页区块
- `app/src/main/java/com/example/zhishu/ui/ZhishuApp.kt` —— 顶层挂载点（autoCheckIfNeeded + UpdateDialog）
- `app/src/main/java/com/example/zhishu/data/prefs/LearningPrefs.kt` —— 自动检查开关 + 上次检查时间
- `app/src/main/AndroidManifest.xml` —— `REQUEST_INSTALL_PACKAGES` 权限 + FileProvider 声明
- `app/src/main/res/xml/update_file_paths.xml` —— FileProvider 只开放 updates/ 子目录
- `app/build.gradle.kts` —— versionCode=提交数、统一签名、buildConfig
- `keystore/app.keystore` —— 统一签名钥匙（本机调试钥匙副本）
- `.github/workflows/build-release.yml` —— 云端自动构建发版
- `app/src/test/java/com/example/zhishu/data/update/UpdateCheckerTest.kt` —— 纯 JVM 单测

## 对外接口 / 被谁调用

- `ZhishuRoot` 调 `UpdateViewModel.autoCheckIfNeeded()`（启动静默检查）并把 `UpdateDialog(updateVm)` 挂在 Scaffold 之外。
- `SettingsScreen(updateVm = ...)` 接收同一个 ViewModel，渲染「应用更新」区块。
- 对外网络依赖只有一个：GitHub API `releases/latest` 与 Release 资产下载。

## 依赖的上游模块

- `LearningPrefs`（偏好存储）：自动检查开关、上次检查时间戳。
- 构建配置（`app/build.gradle.kts`）：`BuildConfig.VERSION_CODE/VERSION_NAME`（开了 `buildConfig = true`）。
- AndroidX Core 的 FileProvider。

## 关键数据结构

- `ReleaseInfo(versionCode, versionName, notes, apkUrl, apkSize)` —— 远端最新版信息。
- `UpdateCheckResult` = `Available(ReleaseInfo)` | `UpToDate(remoteVersionName)`。
- `UpdateMeta(versionCode, versionName)` —— 从发布说明第一行注释解析出的机器可读元数据。
- GitHub Release 约定：tag 恒为 `latest`，资产名恒为 `Zhishu-latest.apk`，说明第一行为 `<!-- zhishu-update versionCode=N versionName=0.1.N -->`。

## 已知坑与约束

- **CI 三坑（已修）**：① Windows 提交的 `gradlew` 会丢执行位，已 `git update-index --chmod=+x`（提交后须为 100755）；② 机器专属 `org.gradle.java.home` 绝不能进 `gradle.properties`（JDK 交给各环境）；③ 阿里云镜像被 GitHub 美国服务器访问会 502——`settings.gradle.kts` 已按 `CI=true` 环境变量分流，CI 直连官方仓库（条件必须内联在 `pluginManagement` 块里，引用文件级变量会编译失败）。
- **改仓库名要同步两处**：`UpdateChecker.REPO` 和 git remote。
- **覆盖安装规则**：相同 versionCode 允许重装，更低的 versionCode 会被系统拒绝——测试发布时不要用比已装版本小的号。
- **签名钥匙已公开**：`keystore/app.keystore` 是调试钥匙副本随仓库公开（口令 android）。签名一致不授予任何安装/数据权限，个人项目风险可控；若将来要上应用商店，换正式钥匙。
- **匿名限流**：GitHub 匿名 API 60 次/小时，自动检查已 24 小时节流，正常使用远够；手动狂点检查更新遇到 403 就是限流，稍后再试。
- **单测不能用 `com.sun.net.httpserver`**（AGP 单测编译的 JDK 模块限制），用 `ServerSocket` 手写假 GitHub，见 `UpdateCheckerTest.kt`。
