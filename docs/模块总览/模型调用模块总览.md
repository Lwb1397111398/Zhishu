# 模型调用模块总览

## 模块职责（一句话）

把「一次业务生成」（写一章正文、出一版契约、跑一次核验……）变成对 OpenAI 兼容服务商的 HTTP 调用，并在中间处理掉所有「网不稳定、服务商挑剔、模型磨蹭」的问题，让上层拿到的只有「成功的内容」或「一句人话的失败原因」。

## 运作流程（一次正文生成的真实路径）

以「写第 3 章正文」为例，按数据流动顺序：

1. **上层发起**：`PipelineService.runChapter`（`ai/pipeline/PipelineService.kt`）拼好 prompt，调 `router.generate(...)`，只声明「我要 STORY 角色的模型、这段 prompt、最多 12000 输出 token、JSON 模式」。
2. **路由限流**：`DefaultModelRouter.generate`（`ai/DefaultModelRouter.kt`）管住本次业务生成的总预算——最多 4 次模型调用（`maxProviderCalls`），含重试与 JSON 修复；每次失败按 2s/5s/15s 退避，429 优先听服务端的 Retry-After。
3. **Provider 发请求**：`OpenAiModelProvider.complete`（`ai/OpenAiModelProvider.kt`）真正发 HTTP。**默认流式**（`stream=true`）：中转站网关普遍按「N 秒无响应」掐断非流式连接，流式连接持续有数据就不被掐。走专用的 `streamClient`。
4. **流式读与三道超时**（`readStreamResponse`）：
   - **首字超时 90 秒**（`firstTokenTimeoutMillis`）：靠 OkHttp 引擎 readTimeout 实现，200 后一个字节不吐（限流排队）就秒级断开；
   - **正文硬超时 10 分钟**（`bodyStallHardTimeoutMillis`）：中转站排队时每分钟发 SSE 心跳注释行（`: keep-alive`）——字节一直在来，readTimeout 永不触发；这道在**读循环里**按「距上一条正文数据（`delta.content` / `reasoning_content`，检查在任何 continue 之前做）的时长」判死，心跳与注释行不算数。2026-09-14 加的，之前这里能无限挂死（界面停在「正在写正文」几十分钟，诊断日志一行不落）；
   - 超时/断流都抛 `StreamFallback` → **降级非流式重发一次**，并把本实例标记为 `streamUnusable`（本次业务生成内不再试流式）。
5. **参数降级**：服务商不认识 `thinking` / `stream_options` / `stream` 参数时（按错误原文关键词识别），剥掉对应字段原样重发；嫌 max_tokens 太大时逐档减半（不占调用预算）。
6. **内容判定**（`judgeOutput`）：非空成功；`finish_reason=length` → Truncated（不可重试，交给上层「少要点」自救）；只有思考没正文 → 提示换普通对话模型；空返回 → Empty（可重试一次）。
7. **错误分类**（`classify`）：401/403 → Auth（带人话翻译）、429 → RateLimited、4xx → InvalidRequest（不可重试）、5xx → Server（可重试）。
8. **解析与修复**：原始响应交给上层的 decoder 解析 JSON；解析失败由路由层 `repair` 再调一次模型修 JSON（最多 1 次，也占预算）。
9. **诊断落日志**：每次调用结束（成败都算）`GenerationLog.record` 落一行结构化记录到 `diagnostics/generation.log`（最多 500 行）——阶段、输入字符数、token、耗时、错误类别；**绝不写 API Key、prompt 原文、完整响应体**。设置页「导出诊断」读的就是它。

## 入口文件清单

| 文件 | 干什么 |
| --- | --- |
| `app/src/main/java/com/example/zhishu/ai/OpenAiModelProvider.kt` | HTTP 调用、流式解析、超时与降级、错误分类 |

## 对外接口 / 被谁调用

- `ModelRouter.generate`：被 `PipelineService` 的所有阶段调用（知识地图、路线、契约、正文、核验、出题）。**调用结束后**（`ConfiguredModelRouter.generate` 包装层）会把本次总 token 写进协程上下文里的 `UsageTrackerElement`（`ai/UsageTracker.kt`）——`GenerationWorker` 在每个 WorkRequest 外面挂一个 `UsageAccumulator`，状态条实时显示「已用 X tokens」，完成通知带本次生成总用量；Worker 侧再把用量合并进 `AppContainer.sessionTokenUsage`（按生成会话记账的内存台账，进程被杀就只剩「约」数，不装精确）。
- `OpenAiModelProvider.listModels`：被设置页「测试连接」调用。
- `GenerationLog.read`：被设置页「导出诊断」调用。

## 依赖的上游模块

- `domain/model/ApiProfile`：接口地址、模型名、max_tokens、temperature（用户在「我的」页配置）。
- ktor-client（OkHttp 引擎）：HTTP 与 SSE。
- 密钥由上层注入，本模块只透传、绝不落日志。

## 关键数据结构

- `ModelRequest`：一次生成的输入（role/system/user/maxTokens/jsonMode/temperature）。
- `ModelError`（sealed）：Auth / InvalidRequest / RateLimited / Server / Network / Decode / Empty / Truncated / BudgetExhausted / Invalid，`retryable` 决定路由层是否重试。
- `StreamChunk`：SSE 单行 `data: {...}` 的最小解析结构。
- `CallAttempt` / `ModelCallStats`：每次 HTTP 尝试与按类别的累计统计。

## 已知坑与约束

- **流式客户端不能装总超时**：实测（ktor 2.3.12 + OkHttp）装了 HttpTimeout 或 callTimeout 会让 readTimeout 失效、一路挂死。所以 streamClient 只设引擎 readTimeout，总时长控制靠读循环里的正文硬超时。
- **`withTimeout` 掐不住引擎阻塞读**：协程层超时对 OkHttp 阻塞读无效，别想着用它替代上面的机制。
- **classify 的 4xx 文案不能带「上下文/token/长度」字样**：token 降档判定 `looksLikeTokenLimit` 靠关键词识别，包装文案塞进这些词会让所有 4xx 都被误降档（已修过一次，别再犯）。
- **`[DONE]` 之前没收到 finish_reason 且已有正文** → 按「中途断流」降级非流式，不算成功。
