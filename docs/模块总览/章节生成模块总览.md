# 章节生成模块总览

## 模块职责（一句话）

把「一份章节计划」变成「一篇已发布、可阅读的章节正文」：带上本章该讲的知识点调模型写正文、做确定性校验与修复、核验、自动修复、发布；每一步失败都按类型降级处理，原则是**正文写出来了就不作废**。

## 运作流程（点「生成章节」之后发生什么）

调度链：章节卡片「生成 / 重新生成」→ `GenerationEnqueuer`（WorkManager 排队）→ `GenerationWorker.runChapter` → `PipelineService.generateChapter` → `runChapter`（`ai/pipeline/PipelineService.kt`）。以下按 `runChapter` 内部的真实顺序：

1. **门口一道闸（契约闸）**：`plan.contractStatus != DONE` 直接失败，提示去讲述路线「补契约」。有正文必有契约——正文按契约的拍子写、核验也按它逐项查。
2. **建草稿版本**：`insertDraftVersion` 新建一个独立版本行。读者看到的仍是旧版，直到发布时原子切换；失败则这个草稿作废，旧正文一个字不动。
3. **知识点解析与兜底（2026-09-14 加）**：
   - 正常路径：`plan.nodeIds`（规划时挂的知识点 ID）对回地图节点，得到本章 `nodes`；
   - 兜底路径：`nodeIds` 为空时，`nodesFromContract` 从 `plan.contractJson` 反解契约的 `introducedNodeTitles` + `appliedNodeTitles`，按标题对回地图节点；拿到就**回填 plan.nodeIds 落库**（自愈，出题和记忆链都以它兜底）；
   - 终态：契约也拿不出节点 → 在调模型**之前**失败：「第 N 章没有关联任何知识点……」。这是规划数据问题，重试一万次结果一样，晚失败只是白扔上万 token。
4. **拼 prompt 调模型**：`prompts/chapter.txt` 模板，注入 `{nodes}`（`formatNodesWithDerivation`：标题 + 定义 + 来处去处 + 易混点）、推演骨架、世界设定、上一章结尾状态、因果契约等。STORY 角色、temperature 0.85、JSON 模式。调用/网络失败 → `failAttempt`（草稿作废、章节标 FAILED）→ Worker 层退避重试。
5. **确定性校验与修复**（`OutputValidators.validateChapter`）：
   - 正文为空 → 拒收；
   - `relinkKnowledgeNodeTitles` 两步把模型回传的标题对齐到真实标题：**变体归位**（`normalizeTitle` 抹掉标点空格后比对）+ **文内取证**（讲解段落正文里真实出现过的标题补上关联）。修复结果随校验通过流回，真实落库；
   - FACT 段落至少要一条可追溯的资料引用（无资料模式豁免）；
   - **讲解段落全没关联知识点不再拒收**（2026-09-14 改）：记 `nodeLinksMissing` 标记继续往下走。
6. **程序化文风预检（2026-09-26 加）**：`StoryQualityChecks.check(blocks)` 免费抓机器能判定的硬信号——提示词例句复读 ≥2 次、同一长句章内重复、全章零对话、STORY 块占比 < 50%。产出 `type=style` 的 `VerificationIssueDto`，与核验结果合并落库；短章（< 800 字）不做整体判定，阈值宁漏勿误。
7. **落库**：块转成 `ChapterBlock`（`knowledgeNodeTitles` 反解成节点 ID）；引用交给 `CitationResolver` 逐条记 RESOLVED / UNCONFIRMED；草稿版本置 VERIFYING。
8. **核验**（`verifyChapter`）：VERIFY 角色、temperature 0，拿着计划摘要（类型 + 契约）逐项对正文。
   - 核验**调用**挂了（网络/超时/解析）→ 正文照常发布，说明写「核验没跑完」，留「更多 → 重新核验」只补查不重写；此时文风预检的结论**照样落库**（它是程序算的，与核验无关）；
   - 核验出**问题** → `IssueRecorder` 逐条落库（定位到块、带建议修法）。问题类型含 `STYLE`（文风问题）：全章独白无人物、教科书腔、口头禅复读。
9. **自动处理（2026-09-27 起，默认开）**：`autoHandleIssues` 开关（「我的 → 学习方式」）开着时不再「修不动就停下等人」：
   - **两轮自动修复**：问题定位得到块且涉及 ≤6 块（`AUTO_REPAIR_MAX_BLOCKS`）→ `runRewrite` 逐段重写再整章重核；一轮修完仍有问题就重取剩余问题块集合再来一轮（`AUTO_REPAIR_ROUNDS = 2`）。开关关闭保持旧的一轮。
   - **文风问题自动放过**：修复轮结束后仍未解决的 `STYLE` 问题（程序化文风预检产物）自动标记「不用改」（`IssueResolution.ACCEPTED`，附人话说明），不再拦发布——它本来就不是事实错误，反复弹给用户只会把人挡在正文外面。
   - **事实类问题绝不自动放过**：编造出处、自相矛盾等一律保留待复核，链尾通知里汇总「自动修复 N 章，M 章剩 X 个问题待看」。**注意：`runRewrite` 里只并入「定位到段落」的文风问题**——全章级文风问题（零对话、占比低）重写一段修不掉，若也拦发布，局部重写会永远发不出去。
10. **发布与降级**（`publishVersionAtomically` 原子切换 activeVersionId）：
   - 全干净 → PUBLISHED；
   - 有核验问题、或 `linksStillMissing`（自动处理**之后**重算：讲解段仍全无关联）→ NEEDS_REVIEW + 人话说明（`issueSummary` / `NODE_LINK_MISSING_NOTE`）。自动处理开着时 NEEDS_REVIEW 名单只剩事实类问题（文风类已自动标记不用改）。
11. **收尾**：`advanceMemory` 改写滚动记忆（runningState 是改写不是追加，长度不随章数涨）→ `writeBackNodeChapters`（节点 ↔ 章节互链）→ `scheduleReviews`（间隔复习开关开着才排）→ `generateQuiz`（出题失败只记 quizState.FAILED，不拖累正文）。

## 对外接口 / 被谁调用

- `generateChapter`：`GenerationWorker`（单章 / 首章阶段）、章节列表「重新生成」。
- `generateStoryBible`（含大纲 + 逐章契约）：一键开讲、重新规划。**大纲同时产出故事脚手架**（2026-09-26 加）：`route_outline.txt` 要求模型给出 `world`（故事舞台）、`characters`（2-4 个有名有姓的角色）、`approach`（叙事载体理由），`generateStoryBible` 把它们回填进 `StoryBible` 的 world / characters / style / approach——此前这三项永远是空的，正文调用里 `{characters}`/`{world}`/`{style}` 全空，模型只能写无名「他」/「你」的推理独白（「云里雾里」的最大根源）。大纲没给时退回旧值或占位文案，旧行为不变。
- `reverifyChapter`：「更多 → 重新核验」（只查不写）。同样并入程序化文风预检，口径与首验一致。

## 关键数据结构

- `ChapterPlan`：一章的计划。关键字段：`nodeIds`（本章知识点）、`contractJson` + `contractStatus`（契约闸）、`status`、`activeVersionId`（读者看哪版）。
- `ChapterContractDto`：因果契约。`introducedNodeTitles` / `appliedNodeTitles` / `requiredBeats` / `resultingChange`……
- `BlockDto` + `BlockType`：正文块。类型 STORY / EXPLANATION / FACT / KEY_POINT / ANALOGY / FICTION；`knowledgeNodeTitles` 由模型填、relink 修复。
- `ChapterAttempt`：一次生成的收尾账本（originalStatus / activeVersionId、version、bodyWritten、published），失败/取消按它恢复现场。
- `ChapterVersion`：一版正文。PUBLISHED（读者在看）/ ARCHIVED（被取代）/ ABANDONED（没通过核验就放弃）。

## 已知坑与约束

- **「一章零知识点」曾是死循环**（2026-09-14 修）：大纲校验只拦「清单外编号」，不拦一章一个编号都不挂；契约校验白名单是「本章 ∪ 已学」，APPLY / REVIEW 章只引用前面章节的节点也合法。两头一夹，`plan.nodeIds` 可以是空的——正文校验白名单随之为空，模型写得再对也被「没有关联到任何既有知识点」拒收，重试永远同样死法。现在双保险：契约 DONE 落库时回填 nodeIds + 生成时 `nodesFromContract` 自愈。
- **relink 的文内取证是字面匹配**：标题（去标点后）真实出现在正文里才算证据，转述不算；找不到不硬造，全空由流水线降级待复核。
- **落库的契约是标题版**：编号（#nk-N）只在规划当次有效；`ContractCodec` 遇 Corrupt 绝不回退成看似正常的空契约。
- **核验失败、出题失败、知识点未关联都不作废正文**：正文是主流程，问题分别走「待补核验」「quizState.FAILED」「NEEDS_REVIEW」。判据区别：`hadReadableBody`（activeVersionId 非空）时失败收尾不能动章节状态——旧正文还在库里可读。
- **版本切换必须走 `publishVersionAtomically`**：原子换指针 + 旧版置 ARCHIVED，中途断电不会出现「章节指向一个没发布的版本」。
