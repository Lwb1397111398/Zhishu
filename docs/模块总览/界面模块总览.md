# 界面模块总览

> **骨架版**：本总览 2026-10-27 首次建立（当日改动 HomeViewModel 后补建）。入口文件清单与共性约束是全量探查过的；各屏的「运作流程」尚未逐一核对到代码级，**动到哪个屏就把那个屏的流程补进来**，不要照抄本文件猜测。

## 模块职责（一句话）

App 全部用户可见界面：书架（学习页）、创建向导、项目详情（大纲/知识/资料）、翻页阅读器、搜索、自测、可信度中心、设置与备份、知识页。导航是单 Activity + Compose Navigation。

## 运作流程（HomeViewModel，2026-10-27 核对）

书架页的数据聚合（`ZhishuViewModels.kt` 内 `HomeViewModel.refresh()`）：

1. 触发：`init` + 每次删除项目 / 载入示例后手动调 `refresh()`；
2. 先算两件全局事：今日到期复习数（`reviewRepository.getDue`）、三模型角色是否配齐（`settingsRepository.missingModelRoles`）；
3. 拉全部项目（`projectRepository.observeAll().first()`），**每本书一个协程并行聚合**（2026-10-27 起；原来逐本串行三连查，书越多首页越慢）：章节数/可读数/继续阅读入口（`chapterRepository.getPlans` + `progressRepository.get`）、知识点数（`knowledgeRepository.getByProject`）；
4. 结果写四个 StateFlow：`bookStats`（封面下进度行）、`knowledgeStats`（知识页统计）、`continueEntry`（全书最近读的一本）、`weekReadCount`（近 7 天读过的书数）；
5. 备份提醒：有已发布章节且超两周没备份 → `backupReminder`（可关闭，`learningPrefs.lastBackupAt` 为准）。

失败兜底走基类 `ZhishuViewModel.launchSafely`：失败 1.5 秒后重试一次（覆盖数据库自愈窗口），仍失败只记日志——界面协程异常不允许杀死进程。

## 对外接口 / 被谁调用

- `MainActivity` 装配 NavHost；通知点击经 `EXTRA_PROJECT_ID` deep-link 回项目/阅读器。
- 调度层：生成按钮 → `GenerationEnqueuer`（见 [生成调度模块总览](生成调度模块总览.md)）。
- 自更新：设置页/弹窗 → `UpdateViewModel`（见 [应用自更新模块总览](应用自更新模块总览.md)）。

## 依赖的上游模块

- 数据层仓储与 Prefs（全部查询经 ViewModel）；生成调度（入队/取消）；搜索（FTS）；应用自更新（检查更新 API）。

## 关键数据结构

- `HomeViewModel.BookStat`（每本书的章节统计）、`ContinueEntry`（继续阅读入口）、`PendingSource`（向导中的待解析资料）。
- 阅读进度三坐标：章节 + 正文块 + 块内偏移（数据层，阅读器只消费）。

## 已知坑与约束

- **5 个千行级大文件**（ProjectDetailScreen 2404 / ReaderScreen 1606 / SettingsScreen 1164 / HomeScreen 1011 / ReaderPager 988）+ ZhishuViewModels 2003 行：改一处易牵动全局，动到哪个屏时优先顺手拆那个屏。
- **全 App 级 Spacing/字号令牌不存在**：阅读器内部有自己的 `ReaderLayout`/`ReaderTypography`，其余各屏 dp 字面量内联——2026-09 改版方案的 P3 只落了阅读器一半。
- **国际化零准备**：几百处中文直接写在 Compose 代码里，strings.xml 只有 app_name；将来上架或给他人用需先做 i18n 抽取。
- **无障碍薄弱**：contentDescription 全源码仅 43 处（25 处 null），书卡等大面积可点区无语义标签。
- **夜间模式**：跟随系统 Light/Dark，无应用内开关、无 Material You 取色；阅读器有独立纸色（米白/纯白/夜间）。
- HomeViewModel 的书架统计无专属单测（当日全量基线中无引用 HomeViewModel 的测试类）。
