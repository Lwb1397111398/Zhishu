# 生成流程自动化闭环 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 点一次「继续」即自动写到主线讲完：逐章生成、卷末自动续卷、漏知识点自动补，全程失败自动重试，待复核不阻断。

**Architecture:** 保留现有静态展开的 WorkManager 链，只在「当下算不出步数」的接缝插入一个不调模型的 `ADVANCE` 决策 Worker——它查库决定下一步，用 `ExistingWorkPolicy.APPEND` 把后续工作挂到同一条项目唯一链上，并在链尾自我续订。卷门判定（新增谓词 `isVolumeBlocking`）从 `isReadable` 放宽为「没有仍在生成中的章」，且 `nextVolumeAvailability` 与 `generateNextVolume` 共用同一谓词。

**Tech Stack:** Kotlin / Jetpack Compose / Room / WorkManager 2.9.1 / kotlinx-coroutines / JUnit4 + Robolectric + androidx.work:work-testing。

**规格：** `docs/superpowers/specs/2026-09-09-自动化闭环-design.md`

**测试命令（Windows，本仓库既有约定）：** `./gradlew.bat testDebugUnitTest --tests "com.example.zhishu.<类名>" --max-workers=1`

**关键既有事实（实现者必读，零上下文）：**
- `ChapterStatus.isReadable = PUBLISHED || QUIZ_FAILED`（`domain/model/Chapter.kt:34`）。`NEEDS_REVIEW` 与 `FAILED` 都不算可读。
- 核验带问题发布走的是 `Result.success`（`ai/pipeline/PipelineService.kt:2122-2150`）→ 单章停在 NEEDS_REVIEW **不会**断 WorkManager 链。真正断链的只有 `Result.failure`（重试 3 次仍失败，`worker/GenerationWorker.kt:188`）。
- 卷门有**两处**，必须同改：`nextVolumeAvailability`（按钮显示，`PipelineService.kt:1579`）与 `generateNextVolume` 内部拒绝（`PipelineService.kt:1609`）。
- `selectChaptersToGenerate(plans, includeNeedsReview=false)`（`worker/GenerationStage.kt:73-89`）已排除 `contractStatus=FAILED` 与 `isReadable`；`volumeIndex` 从 0 起，`plans.maxOf{volumeIndex}` 即当前卷。
- `CoverageReport.pendingNodes` 是「已排进章节计划但尚未生成出正文」的知识点，**不为空时禁止规划下一卷**（`PipelineService.kt:1609`）。
- `generateNextVolume` 是 append-only：只 `upsertPlans` 新章节，绝不 clear、绝不改已发布章节（`PipelineService.kt:1676-1711`）。
- prefs 单例走 `AppContainer`；已有全局行为开关先例 `spacedReviewEnabled = { learningPrefs.spacedReviewEnabled.value }`（`di/AppContainer.kt:104`，`data/prefs/LearningPrefs.kt:23-31`）。

`PipelineService.kt`，`dismissGap`（`:824-834`）之后新增：

```kotlin
    /**
     * 自动补「漏掉的知识点」（自动化闭环）。总开关开启时在知识主干审计完成后调用。
     *
     * 只补 [GapStatus.OPEN] 且 `actionable`（= [GapType.MISSING_NODE]）的缺口——
     * 免责提示型（过时/地区差异/说法不一/无法核实）本就不该被自动关掉，要一直提醒用户核实。
     *
     * 复用 [generateKnowledgeMapPatch]（已幂等：同名节点直接标 RESOLVED，不重复烧调用），
     * 不产生第二套补节点逻辑。单条失败不中断其余：gap 留 OPEN，下次点「继续」再补。
     * [limit] 是成本护栏——补一条 = 一次模型调用。
     *
     * @return 实际补上的条数
     */
    suspend fun autoResolveGaps(projectId: String, limit: Int = 10): Int {
        val targets = knowledgeRepository.getGaps(projectId)
            .filter { it.gapStatus == GapStatus.OPEN && it.actionable && it.suggestedTitle.isNotBlank() }
            .take(limit)
        var done = 0
        for (g in targets) {
            if (generateKnowledgeMapPatch(projectId, g.id).isSuccess) done += 1
        }
        return done
    }
```

package com.example.zhishu.worker

/** ADVANCE 查库后的下一步。纯函数 [decideAdvance] 产出，Worker 据此执行。 */
enum class AdvanceDecision {
    /** 总开关关：什么都不追加（用户随时可再点「继续」） */
    StoppedBySwitch,
    /** 当前卷还有在生成的章，且其中有能生成的 → 追加这些章节到链尾 */
    ContinueCurrentVolume,
    /** 卷没完但没有可生成的章（多半整卷卡在「契约未生成」）：发可读通知让用户逐章重试 */
    PausedForUser,
    /** 当前卷已收尾、还有没讲到的知识点 → 追加「规划下一卷」 */
    PlanNextVolume,
    /** 主线讲完（无 pending）→ 发结果通知后停。唯一的自然终点 */
    MainLineDone,
}

/**
 * 决定自动闭环的下一步（决策与执行分离，本函数无副作用）。
 *
 * @param volumeBlockingCount 当前卷 `status.isVolumeBlocking` 的章数（Task 1 谓词）。
 *        待复核/失败 **不算** blocking——这正是「永远第一卷」的病根，判定必须用
 *        isVolumeBlocking 而不是 !isReadable。
 * @param generatableCount 当前卷里 selectChaptersToGenerate 会挑出的章数（已排除契约失败）。
 * @param pendingKnowledgeCount coverageReport.pendingNodes.size——还没排进任何章节的知识点数。
 *
 * 判定顺序即优先级：先看开关，再看本卷是否还在生成，再区分「有活可干 / 卡住」，
 * 本卷收尾后按 pending 决定续卷还是刹车。
 */
fun decideAdvance(
    autoOn: Boolean,
    volumeBlockingCount: Int,
    generatableCount: Int,
    pendingKnowledgeCount: Int,
): AdvanceDecision {
    if (!autoOn) return AdvanceDecision.StoppedBySwitch
    return when {
        volumeBlockingCount > 0 ->
            if (generatableCount > 0) AdvanceDecision.ContinueCurrentVolume
            else AdvanceDecision.PausedForUser
        pendingKnowledgeCount > 0 -> AdvanceDecision.PlanNextVolume
        else -> AdvanceDecision.MainLineDone
    }
}

     * （竞态窗口），替换而非丢弃，避免续订丢失导致静默停摆。仍共用同一唯一名，

     * [session] 由调用方 Worker 从 inputData 透传，保证链上会话 tag 一致，UI 不把它当「另一次生成」。

    suspend fun appendAutoChunk(
        context: Context,
        projectId: String,
        session: String,
        chapterIds: List<String>,
        chapterLabels: List<String>,
        unitsTotal: Int,
    ) {
        val manager = WorkManager.getInstance(context)
        var continuation: WorkContinuation? = null
        chapterIds.forEachIndexed { index, id ->
            val req = chapterRequest(
                projectId = projectId, chapterId = id,
                label = chapterLabels.getOrElse(index) { "" },
                session = session,
                unitsBefore = index * ChapterPhase.UNITS_PER_CHAPTER,
                unitsTotal = unitsTotal,
            )
            continuation = continuation?.then(req)
                ?: manager.beginUniqueWork(
                    GenerationWorker.uniqueWorkName(projectId),
                    ExistingWorkPolicy.APPEND_OR_REPLACE,
                    req,
                )
        }
        val summary = summaryRequest(projectId, session, unitsTotal)
        val advance = request(
            session = session,
            data = baseData(projectId, GenerationStage.ADVANCE, session, unitsTotal, unitsTotal),
        )
        continuation = continuation?.then(summary)?.then(advance)
        continuation?.enqueue()?.result?.await()
    }

- [ ] **Step 4: 实现 `advance()`**

`GenerationWorker.kt`，`summarize` 方法附近新增：

```kotlin
    /**
     * 自动闭环的一步：查库 → decideAdvance → 续订或刹车。全程只读库 + 调 WorkManager，
     * 不调模型（模型调用在 APPEND 出去的新 WorkRequest 里，各自带退避重试）。
     */
    private suspend fun advance(): Result {
        val autoOn = container.learningPrefs.generationAutoAdvance.value
        val plans = container.chapterRepository.getPlans(projectId)
        val currentVolume = if (plans.isEmpty()) 0 else plans.maxOf { it.volumeIndex }
        val volumePlans = plans.filter { it.volumeIndex == currentVolume }
        val blocking = volumePlans.count { it.status.isVolumeBlocking }
        val targets = selectChaptersToGenerate(volumePlans, includeNeedsReview = false)
        val session = inputData.getString(KEY_SESSION).orEmpty()

        val pendingCount = when (val av = container.pipeline.nextVolumeAvailability(projectId)) {
            is NextVolumeAvailability.CanContinue -> av.pendingCount
            NextVolumeAvailability.MainLineDone -> 0
            // NoPlanYet / CurrentVolumeUnfinished：一定还有 blocking 或根本没章，交给 blocking 分支决定
            else -> Int.MAX_VALUE
        }

        when (decideAdvance(autoOn, blocking, targets.size, pendingCount)) {
            AdvanceDecision.StoppedBySwitch -> GenerationNotifier.clearProgress(applicationContext)

            AdvanceDecision.ContinueCurrentVolume -> GenerationEnqueuer.appendAutoChunk(
                context = applicationContext, projectId = projectId, session = session,
                chapterIds = targets.map { it.id },
                chapterLabels = targets.map { "第 ${it.order} 章（自动）" },
                unitsTotal = targets.size * ChapterPhase.UNITS_PER_CHAPTER,
            )

            AdvanceDecision.PlanNextVolume -> GenerationEnqueuer.appendVolumePlan(
                context = applicationContext, projectId = projectId, session = session,
            )

            AdvanceDecision.PausedForUser -> GenerationNotifier.notifyOutcome(
                context = applicationContext, projectId = projectId,
                projectTitle = container.projectRepository.get(projectId)?.title.orEmpty(),
                outcome = GenerationOutcome.PARTIAL,
                detail = "剩下的章节的因果契约没生成，不能自动往下写。请到「讲述路线」逐章点「重试契约」后再继续。",
            )

            AdvanceDecision.MainLineDone -> GenerationNotifier.notifyOutcome(
                context = applicationContext, projectId = projectId,
                projectTitle = container.projectRepository.get(projectId)?.title.orEmpty(),
                outcome = GenerationOutcome.COMPLETED,
                detail = "主线讲完了：知识主干上的知识点都已安排进章节并写完。想再读可在讲述路线点「扩展阅读」另起一卷。",
            )
        }
        return Result.success()
    }
```
