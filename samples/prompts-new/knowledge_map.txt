你在为一个学习者整理一门学科的「知识主干」。

最重要的一条：**不要产出目录**。目录式的知识点罗列（"民事主体、物权、债权、侵权……"）对学习者毫无价值。他要的是一条能走通的路径——一个制度为什么会从前一个制度里长出来，又为什么必然走向下一个。

## 你要做的事

把这门学科整理成一条**演进主干**。主干上的每一站都是一个「问题 → 回答」：

- 上一站已经解决了什么
- 于是暴露出什么新问题
- 为了回答这个新问题，出现了什么制度／概念
- 这个制度自身又留下什么没解决的口子（引出下一站）

## 输出结构

- `nodes`：知识节点。层级不超过 3 层，用 `parentTitle` 表达父子关系，根节点 `parentTitle` 为 null。
- 节点数量：入门 14-22 个，考试 24-36 个，专业 32-44 个。
- 每个节点必须给出：
  - `definition`：这个概念解决的是什么问题（不要写词典式定义，要写"它是为了回答什么才存在的"）
  - `arisesFrom`：它从哪个前序概念、因为什么缺口才出现（一句话；根节点写这门学科的起点问题）
  - `leadsTo`：它自身没能解决、因而引出下一个概念的那个口子（一句话）
  - `prerequisites`、`related`、`confusions`、`examples`
  - `sourceRefs`：引用资料片段 ID
- `chains`：3-8 条演进链。每条 `nodeTitles` 是一串节点标题，按「前一个制度长出后一个」的顺序排列，`theme` 一句话说明这条链在回答什么，`opening` 说明这条链从学习者能直接感知的什么处境开始讲。
  这些链会被直接用作章节骨架，所以每条链必须能独立讲成一段连贯推演，不要把互不相关的概念硬串在一起。
- `gaps`：资料没覆盖但这门学科绕不开的内容。
- `conflicts`：资料互相矛盾之处。**不要自行裁决**，必须列出涉及来源。

## 硬性要求

1. `arisesFrom` 与 `leadsTo` 必须真的咬合：把 nodes 按 chains 串起来读，应当读出一条连续推理，而不是若干张卡片。
2. 每个必学节点至少引用一个资料片段 ID。**只能用下面列出的片段 ID，原样复制，不要改写或自己编。**
   编出来的 ID 不会变成来源，只会被记成「未确认」直接展示给学习者。
3. 资料没说的内容放进 `gaps`，不要写进 `definition` 冒充资料内容。
4. 只输出 JSON 对象，不要输出任何其他文字或代码块标记。

主题：{topic}
学习深度：{depth}
学习目标：{goal}
学习者当前水平：{baseline}
资料片段（每段都标了它出自哪份资料的哪一页哪一节、什么版本、哪个法域——
凡是只在某个法域或某个时间之后成立的内容，写进 `definition` 时要说清这个前提，不要讲成普适规则）：
{chunks}
